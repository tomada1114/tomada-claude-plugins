# 中立語彙集（本文用）

対象スキルの本文（SKILL.md・references/・templates/）は、**プラットフォーム固有のツール名を書かない**。書いてよいのは各スキルの `references/platform-notes.md`（`<!-- platform-annex -->` を先頭に持つファイル）だけ。

| Claude 固有構文 | 本文に書く中立表現 |
|---|---|
| `AskUserQuestion` | 「選択肢を 2〜4 個、トレードオフと推奨を添えて提示し、ユーザーの回答を待つ（1 ラウンド最大 4 問）」 |
| `TodoWrite` | 「完了したフェーズをチェックリストで追跡する」 |
| `Task` 並列 fan-out | 「独立した調査は、委譲できる環境なら並列に委譲し、できなければ同じ調査を逐次で行う。フェーズ順序は必ず保つ」 |
| `Skill` 呼び出し（他スキル起動） | 「`<name>` スキルを使う」（ツール名を書かず名前参照のみ。解決は各ホストに任せる） |
| `context: fork` | 本文では触れない（frontmatter にのみ書く） |
| `run_in_background` | 「並行実行できる環境なら並行、できなければ逐次」 |
| `/code-review` などの組み込みスラッシュコマンド | 「セルフレビュー手段があれば実行し、無ければ利用不可として続行する」 |
| MCP ツール（`mcp__*`） | 「<機能>を行うツール」＋フォールバック手順。具体名は platform-notes 側 |
| `isolation: "worktree"` | 「並列実装が必要なら作業単位ごとに隔離した作業コピーを使う」 |

## 適用ルール

1. **ツール名の唯一の置き場所は `references/platform-notes.md`。** 本文（SKILL.md・その他 references）には一切書かない。frontmatter の `allowed-tools`/`disallowed-tools` は例外（Codex は無視するフィールドなので残してよい）。
2. **代替手順は使用箇所にインラインで書く。** 末尾の劣化注記は索引であって唯一の置き場ではない（→ transformation-rules.md R11）。
3. 中立表現は「意図」を保つ。手順・判断基準・デフォルト値は変えない。
4. 迷ったら「ユーザーとの対話」「委譲できるかどうか」で書く。「どのツールで」は書かない。
