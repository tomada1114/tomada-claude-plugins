# 競合/人気アプリ調査手法

WebSearchを使用してUXトレンドと競合アプリを調査する手法。

---

## 調査の目的

1. **ベストプラクティスの発見** - 成功しているアプリのUXパターンを学ぶ
2. **避けるべきパターンの特定** - ユーザーから批判されている設計を避ける
3. **差別化ポイントの発見** - 競合との違いを明確にする
4. **最新トレンドの把握** - 2025年以降のUI/UXトレンドを把握

---

## 調査結果の整理方法

### 1. 強み（Strengths）

アプリが優れている点を記録する。

```markdown
## [App Name] の強み

### UI
- ポリッシュされたインターフェース
- 直感的なナビゲーション
- 一貫したデザインシステム

### UX
- オンボーディングがスムーズ
- 即時フィードバック
- 低い学習コスト
```

### 2. 弱み（Weaknesses）

改善が必要な点を記録する。

```markdown
## [App Name] の弱み

### UI
- 情報過多の画面がある
- タップターゲットが小さい

### UX
- フィードバックが浅い
- カスタマイズ性が低い
```

### 3. 避けるべきパターン（Anti-patterns）

ユーザーから批判されているパターンを記録する。

```markdown
## 避けるべきパターン

| パターン | 問題点 | 代替案 |
|---------|--------|--------|
| 毎回質問で終わる | 尋問のように感じる | 自然な会話の流れ |
| 強制的な通知 | ユーザー離れ | オプトイン |
| 隠れた料金 | 信頼低下 | 事前に明示 |
```

## 調査結果のユーザーへの共有

### 共有フォーマット

```markdown
## 調査サマリー

### 参考にしたアプリ

| アプリ | 強み |
|--------|------|
| **[App A]** | ロールプレイに明確な目的設定、自然終了の会話設計 |
| **[App B]** | ゲーミフィケーション、即時フィードバック |
| **[App C]** | 直感的UI、明確なスコアリング |

### 避けるべき課題

- [App A]の「毎回質問で終わる」パターン → 尋問のように感じる
- フィードバックが浅い/パーソナライズ不足
- 構造化学習 vs 自然な会話のジレンマ

### 調査で参考にしたソース

- [Source 1](URL) - 概要
- [Source 2](URL) - 概要
```
