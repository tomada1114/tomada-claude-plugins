## パレット選定の原則

1. **既製フレームワークの既定色をそのまま使わない。** Tailwind の `blue-500` / `violet-500` / `green-500` をニュートラルグレーと組み合わせた画面は、どこかで見た見た目になる。色相を10〜20度ずらし、彩度を落とすだけで固有性が出る。
2. **ニュートラルに色を混ぜる。** 純グレー（C=0）ではなく、アクセントの色相を `C = 0.003〜0.020` で混ぜた色付きニュートラルにする。理由: 背景・境界・文字がアクセントと同じ色相軸に乗るので、画面全体が一つの色として調和する。
3. **アクセントは1色に絞る。** 2色目はステータス用途にだけ使う。理由: 主要アクションが複数の色を持つと、どれが次の一手か分からなくなる。
4. **ブランドの軸でアクセントを選ぶ。** 「好きな色」ではなく、プロダクトが約束していること（信頼か、成長か、速さか）を色相に写す。判断材料は下の連想表を使う。
5. **アクセント上の文字色を先に決める。** 塗りつぶしボタンは最も使われる部品なので、ここが不適合だと影響が全画面に及ぶ。決め方は各パレットの `--color-text-on-accent` を参照する。

以下の5パレットは出発点であり、そのまま採用してよいという意味ではない。色相を動かしたら、動かした後の値でコントラストを測り直す。

## 中立色の共通レシピ

中立色は5パレットで構造が同じで、色相 `Hn`（各パレットが指定）だけが変わる。`oklch()` をそのまま CSS に書けばよく、HEX への変換は不要。

| トークン | ライト `L C` | ダーク `L C` | 背景に対する実測比（ライト / ダーク） |
|---|---|---|---|
| `--color-bg` | 0.990 0.003 | 0.175 0.006 | 基準 |
| `--color-bg-subtle` | 0.968 0.006 | 0.145 0.006 | — |
| `--color-bg-elevated` | 1.000 0.000 | 0.215 0.008 | — |
| `--color-surface` | 0.945 0.008 | 0.250 0.010 | — |
| `--color-surface-hover` | 0.918 0.010 | 0.290 0.012 | — |
| `--color-text` | 0.255 0.020 | 0.965 0.004 | 15.17〜15.42 / 17.04〜17.16 |
| `--color-text-muted` | 0.460 0.016 | 0.700 0.016 | 6.85〜6.99 / 7.04〜7.20 |
| `--color-text-subtle` | 0.550 0.014 | 0.590 0.014 | 4.69〜4.74 / 4.58〜4.66 |
| `--color-border-strong` | 0.560 0.012 | 0.585 0.012 | 4.47〜4.55 / 4.48〜4.55 |
| `--color-border` | 0.655 0.010 | 0.495 0.010 | 3.05〜3.09 / 3.07〜3.13 |
| `--color-disabled-bg` | 0.945 0.004 | 0.250 0.006 | — |
| `--color-disabled-text` | 0.700 0.008 | 0.455 0.008 | 2.58〜2.60 / 2.59〜2.62 |

幅があるのは色相によって同じ L でも輝度が変わるため。`--color-border` は 3:1 を満たすので入力欄の枠に使える（1.4.11）。`--color-disabled-text` は 2.6 前後で、コントラスト免除の範囲にありながら文字として見える水準に置いている。

```css
/* 展開例（Hn = 248、パレット1）。他パレットは Hn を差し替えるだけ */
:root {
  color-scheme: light dark;
  --color-bg:            light-dark(oklch(0.990 0.003 248), oklch(0.175 0.006 248));
  --color-bg-subtle:     light-dark(oklch(0.968 0.006 248), oklch(0.145 0.006 248));
  --color-bg-elevated:   light-dark(oklch(1.000 0.000 248), oklch(0.215 0.008 248));
  --color-surface:       light-dark(oklch(0.945 0.008 248), oklch(0.250 0.010 248));
  --color-surface-hover: light-dark(oklch(0.918 0.010 248), oklch(0.290 0.012 248));
  --color-text:          light-dark(oklch(0.255 0.020 248), oklch(0.965 0.004 248));
  --color-text-muted:    light-dark(oklch(0.460 0.016 248), oklch(0.700 0.016 248));
  --color-text-subtle:   light-dark(oklch(0.550 0.014 248), oklch(0.590 0.014 248));
  --color-border-strong: light-dark(oklch(0.560 0.012 248), oklch(0.585 0.012 248));
  --color-border:        light-dark(oklch(0.655 0.010 248), oklch(0.495 0.010 248));
  --color-disabled-bg:   light-dark(oklch(0.945 0.004 248), oklch(0.250 0.006 248));
  --color-disabled-text: light-dark(oklch(0.700 0.008 248), oklch(0.455 0.008 248));
  --color-overlay:       light-dark(rgb(0 0 0 / 0.45), rgb(0 0 0 / 0.65));
}
```

## トーン別パレット

各パレットは中立色相 `Hn` とアクセント色相 `Ha` を指定し、アクセント系5トークンを与える。`--color-focus` は `--color-accent` と同じ値でよい（下表の「アクセント/背景」列が 3:1 以上であることを確認済み）。

### 1. プロフェッショナル・ブルー（`Hn` = `Ha` = 248）

信頼と安定。ブルーを Tailwind 既定（色相 263）より14度シアン側に寄せ、彩度を抑えた実務向けの青。開発者ツール、ダッシュボード、金融、B2B SaaS。

|---|---|---|
| `--color-accent` | `#1274BD` `oklch(0.545 0.140 248)` | `#65A9E7` `oklch(0.715 0.115 248)` |
| `--color-accent-hover` | `#0865A7` `oklch(0.495 0.130 248)` | `#84BBF0` `oklch(0.775 0.095 248)` |
| `--color-accent-active` | `#065893` `oklch(0.450 0.118 248)` | `#4796DC` `oklch(0.655 0.130 248)` |
| `--color-accent-subtle` | `#E3F0FD` `oklch(0.950 0.022 248)` | `#183046` `oklch(0.300 0.050 248)` |

創造性と先進性。Tailwind の violet（色相 293）より12度マゼンタ側に寄せた紫で、AI・メディア系に埋もれにくい。AIアシスタント、クリエイティブツール、音楽/メディア。

## セマンティックステータス色（全パレット共通）

ステータス色はアクセントから独立させる。理由: アクセントを変えるたびに「エラーの赤」が動くと、意味の対応が学習されない。

|---|---|---|---|
| `--color-success` | `#14783F` `oklch(0.505 0.125 152)` | `#6AD18A` `oklch(0.780 0.140 152)` | 5.39 / 10.02 |
| `--color-success-subtle` | `#E4F6E8` `oklch(0.955 0.026 152)` | `#13331D` `oklch(0.290 0.055 152)` | 面（上の文字と 4.92 / 7.31） |
| `--color-warning` | `#875D13` `oklch(0.510 0.100 75)` | `#F2AF48` `oklch(0.800 0.140 75)` | 5.66 / 9.93 |
| `--color-warning-subtle` | `#FCEEDC` `oklch(0.955 0.028 75)` | `#3B2706` `oklch(0.290 0.055 75)` | 面（5.10 / 7.44） |
| `--color-danger` | `#BA242B` `oklch(0.515 0.185 25)` | `#F47B74` `oklch(0.720 0.150 25)` | 6.05 / 7.16 |
| `--color-danger-subtle` | `#FEEBE9` `oklch(0.955 0.020 25)` | `#431F1D` `oklch(0.290 0.055 25)` | 面（5.41 / 5.46） |
| `--color-info` | `#196CB3` `oklch(0.520 0.135 250)` | `#7FB6EE` `oklch(0.760 0.100 250)` | 5.32 / 8.87 |

「面」の比率は、その `-subtle` 背景の上にステータス色の文字を置いたときの値。`--color-text` を載せる場合はライト 13.69〜13.96、ダーク 12.52〜13.09 で、いずれも余裕がある。

## アクセントカラーの心理的な連想

| 色相 | 連想 | 向くプロダクト |
|---|---|---|
| ブルー（240〜265） | 信頼、安定、専門性 | 金融、B2B、ヘルスケア、開発者向け |
| グリーン（140〜165） | 成長、健康、達成 | 学習、フィットネス、環境 |
| パープル（290〜310） | 創造性、先進性、非日常 | AI、クリエイティブ、メディア |
| オレンジ/アンバー（30〜75） | 活動、親しみ、注意 | フード、スポーツ、子ども向け |
| ティール（180〜200） | 落ち着き、清潔、独自性 | ウェルネス、医療、ドキュメント |
| レッド（15〜30） | 緊急、情熱 | ステータス用途に限定するのが安全 |

レッドをアクセントにするなら、エラー色を別の色相（マゼンタ寄りなど）に逃がす。理由: 主要アクションとエラーが同じ色だと、押していいのか危険なのかが判別できない。

## ライト/ダークの色調整ルール

ダークモードの値はライトから機械的に導く。色相 H は固定し、L と C だけを動かす。

```css
/* ライト: 明るい背景の上なので、暗く濃い色 */
--accent-light: oklch(0.545 0.140 248);
/* ダーク: 明度を上げ、彩度は下げる */
--accent-dark:  oklch(0.715 0.115 248);
```

- **L は上げる**（0.52 前後 → 0.72 前後）。理由: 暗い背景に対して十分な明度差を作る。
- **C は下げる**（0.140 → 0.115、およそ 15〜25% 減）。理由: 暗背景上の高彩度は輪郭がにじんで見え（ハレーション）、長文の可読性を落とす。
- **純黒（`#000000`）を背景に使わない。** `L = 0.145〜0.215` の範囲に置く。理由: 純黒と白文字の組み合わせは残像が出やすく、OLED では文字のにじみも起きる。
- **階層は影ではなく背景明度で表す。** ダークでは影がほとんど見えないため、`--color-bg` → `--color-bg-elevated` → `--color-surface` の順に L を上げる。
- **両モードで個別に測る。** ライトで通った比率がダークで通る保証はない。

## エフェクト（任意）

グロー・グラスモーフィズム・グラデーションは必須スロットではなく、プロダクトの性格上必要と判断したときだけ足す。使うなら以下を守る。

```css
/* グロー: アクセントを半透明にして重ねる。文字には掛けない */
--effect-accent-glow: 0 0 24px color-mix(in oklab, var(--color-accent) 30%, transparent);
```

- グローやぼかしを情報の伝達に使わない。理由: `forced-colors: active` では `box-shadow` と `backdrop-filter` が無効化され、表現が消える。
- 半透明の面（グラス表現）の上に文字を置くときは、背景に何が来ても成立するよう不透明の下地色を敷いてからコントラストを測る。
- グラデーションを面に使うなら、最も明るい端と最も暗い端の両方で文字とのコントラストを測る。

## カラー選択の実行手順

上から順に実行し、各項目は判定を伴う。判定できない項目は空欄のまま残さず、確認して埋める。

1. ブランドの軸から色相 `Ha` を決める。連想表の候補から選び、既製フレームワークの既定色相から10〜20度ずらす。
2. 中立色相 `Hn` を決める。`Ha` と同じにするか、±30度以内に置く。純グレー（C=0）は選ばない。
3. 中立色の共通レシピを `Hn` で展開する。
4. アクセントの L と C を決める。まず `--color-text-on-accent` を白で試し、`accent` / `hover` / `active` の3つすべてで 4.5:1 を満たすか測る。満たさないなら、アクセントの L を下げるか、濃色の on-color（`L = 0.20〜0.25`、C はアクセントの 1/3 程度）に切り替える。グリーン・オレンジ・アンバー・ライムは白文字が通らないので後者を選ぶ。
5. `--color-accent` と `--color-bg` の比率を測る。3:1 未満なら、塗りつぶし部品に `--color-accent-active` の枠線を付ける。
6. ダーク値を導出ルール（L を上げ、C を 15〜25% 下げる）で作り、同じ測定を繰り返す。
7. 指定した `oklch()` が sRGB の色域内か確認する。`design-tokens.md` の色域表を超えていたら C を下げる。
8. すべての前景/背景の組み合わせを `scripts/check_contrast.py` に通し、出力をそのまま design-system ドキュメントの表に転記する。記憶や手計算で書かない。
9. 色覚多様性を確認する。手順は `accessibility.md` の「色覚多様性の確認手順」に従う。
10. 情報を色だけで伝えている箇所が無いか、画面を灰色化して確認する。
