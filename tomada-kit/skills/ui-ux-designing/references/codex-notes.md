# Codex での制約（best-effort 劣化）

- `AskUserQuestion`（Phase 1・3・4 の各確認）→ Codex では通常対話で同じ選択肢を提示して確認。「質問設計の原則」（選択肢2〜4個・トレードオフ説明・`（推奨）`明示・3-4個ずつバッチ化）はそのまま適用する。
- `WebSearch`（Phase 2）→ Codex では同等の web 検索ツールがあれば使用、無ければユーザー提供の参考情報で調査（調査観点・3アプリ以上の原則は維持）。

参照（`references/`・`templates/`）はすべてスキル相対パスなので、Claude Code でも Codex（`~/.codex/skills/` の symlink 経由）でも同一に解決する。

## 本文中の個別注記

### Phase 2 — 競合/人気アプリのUX調査
- `WebSearch` が無い環境: 利用可能なら同等の web 検索ツールを使い、無ければユーザーに参考アプリ名・URL・スクリーンショットの提供を依頼して調査する（劣化注記）。

### Phase 3 — デザイン方向性の決定
- `AskUserQuestion` が無い環境: 同じ選択肢を通常の文章でユーザーに提示し、回答を待つ。質問のバッチ化・推奨明示・トレードオフ説明の原則は不変。
