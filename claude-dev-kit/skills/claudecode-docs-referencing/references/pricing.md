# Claude Codeの料金体系

---

## 2つの課金方式

Claude Codeには**サブスクリプション型**と**API従量課金型**の2つの選択肢がある。

| 方式 | 特徴 | 向いているケース |
|------|------|-----------------|
| **サブスクリプション** | 月額固定、コスト予測しやすい | 日常的に使う、予算を固定したい |
| **API従量課金** | 使った分だけ支払い | 使用量が少ない/不定期、細かくコスト管理したい |

---

## サブスクリプションプラン

### Pro プラン（月額$20）

基本的なサブスクリプションプラン：
- Claude Codeの利用
- 拡張思考（Extended Thinking）機能
- ファイル作成機能
- 一定のメッセージ制限あり
- **年払い割引**あり

### Max プラン（月額$100〜$200）

より多くの利用量が必要な方向けの上位プラン：

| ティア | 月額 | 使用量 |
|--------|------|--------|
| **Max 5x** | $100 | Proの5倍 |
| **Max 20x** | $200 | Proの20倍 |

**Max限定機能：**
- 会話をまたいだメモリ機能
- 優先アクセス

**中間プラン（Max 5x）の存在**は他ツールとの差別化ポイント。柔軟にアップグレード/ダウングレードできる。

---

## 使用量制限の仕組み

### ローリングウィンドウ方式
- **5時間ごと**に使用量がリセット
- 制限到達からではなく、**最初に使用した時間から**5時間後にリセット

例）0:10使用開始 → 2:30制限到達 → 5:10リセット

### 使用量が変動する要因

**消費が多くなるケース**
- 大規模なコードベース
- 長い会話の継続
- 大きなファイル添付
- マルチファイルプロジェクト

**消費が少なくなるケース**
- 簡単なスクリプト作成
- 短い会話
- 小さなコンテキスト

### Web版との共有
- claude.ai（Web版）とClaude Codeで**使用量を共有**
- Webで使うとCLIの残量も減る

## トークンとは

トークンはテキストを分割した最小単位。LLMはテキストをトークン単位で処理する。

### トークン数の目安
- 英語：1トークン ≒ 4文字
- 日本語：1文字 ≒ 1〜2トークン（日本語のほうがトークン数が多くなる傾向）

### 入力トークンと出力トークン

| 種類 | 説明 | 含まれるもの |
|------|------|-------------|
| 入力トークン | Claudeに送るテキスト | プロンプト、ファイル内容、コンテキスト情報 |
| 出力トークン | Claudeが生成するテキスト | 回答、生成コード、説明文 |

**出力トークンのほうが単価が高い**（生成処理のほうが計算コストが高いため）

## 各モデルの料金比較（API従量課金）

### Sonnet 4.5（デフォルトモデル）

日常的な開発作業に最適なバランス型モデル。

| 項目 | 料金（100万トークンあたり） |
|------|---------------------------|
| 入力トークン | $3 |
| 出力トークン | $15 |

※ロングコンテキスト（入力20万トークン超）の場合：入力$6、出力$22.50

### Opus 4.5（最高性能モデル）

複雑な推論やアーキテクチャ設計、大規模リファクタリング向け。

| 項目 | 料金（100万トークンあたり） |
|------|---------------------------|
| 入力トークン | $5 |
| 出力トークン | $25 |

常用するには高めなので、計画立案や重要な意思決定の場面で使用。

### Haiku 4.5（高速・低コストモデル）

最も高速かつ低コスト。簡単なタスクに適している。

| 項目 | 料金（100万トークンあたり） |
|------|---------------------------|
| 入力トークン | $1 |
| 出力トークン | $5 |

ファイル検索、確認作業、サブエージェントのモデルとして活用可能。

## モデル選択オプション

| 設定 | 挙動 |
|------|------|
| `opus` | 常にOpus（最高性能、消費大） |
| `sonnet` | 常にSonnet（バランス型） |
| `haiku` | 常にHaiku（高速、消費小） |
| `opusplan` | 計画時Opus、実行時Sonnet（おすすめ） |

- Opusで開発し続けると数十分でSonnetに切り替わることがある
- 拡張コンテキスト（100万トークン）対応モデルもあり

## コスト管理のコマンド

### `/usage` - 使用量確認
現在のセッションで消費したトークン数と料金を確認

```
/usage
```

### `/model` - モデル切り替え
セッション中にモデルを切り替え。タスクに応じて使い分け。

```
/model
```

### `/clear` - コンテキストクリア
コンテキストを完全にクリア。新しいタスクを開始する場合に使用。

```
/clear
```

### `/compact` - コンテキスト圧縮
会話を要約してコンテキストを圧縮。会話を引き継ぎたい場合に使用。

```
/compact
```

---

## コスト管理のヒント

1. **Haikuを活用する** - ファイル検索、Git操作、フォルダ整理などにはHaikuで十分
2. **コンテキストを適切に管理する** - 不要なコンテキストは毎回のリクエストでトークンを消費し続ける
3. **`/usage`でこまめに確認** - 使用量を意識する習慣をつける
4. **タスク完了時に`/clear`または`/compact`** - コンテキストを整理

## プラン選択の考え方

### 使用頻度で判断

| 使用頻度 | 推奨 |
|----------|------|
| 週に数時間 | Pro |
| 毎日数時間 | Max 5x |
| フルタイム開発 | Max 20x |

### サブスクリプション型がおすすめな理由
- コスト予測がしやすい
- 利用料を常に気にする必要がない
- プランの柔軟な切り替えが可能

---

## ⚠️ 変更可能性の高い情報

以下は執筆時に公式で確認推奨：

- 具体的な月額料金（$20, $100, $200等）
- 具体的なメッセージ数上限
- APIの従量課金単価
- 年払い割引率

**料金は頻繁に変更される可能性があるため、記事では「Pro/Max 5x/Max 20xの3段階」という構造と考え方を中心に書くのが安全**
