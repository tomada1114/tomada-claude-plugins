# Claude Code vs Codex CLI：使い分けガイド

Claude Codeをメインで推奨しつつ、Codexが向いているケースも紹介する参照資料。

---

## 基本情報

| 項目 | Claude Code | Codex CLI |
|------|-------------|-----------|
| **提供元** | Anthropic | OpenAI |
| **基盤モデル** | Sonnet 4.5 / Opus 4.5 / Haiku 4.5 | GPT-5.2-Codex / GPT-5.1-Codex-Max / GPT-5-Codex |
| **実装言語** | TypeScript / Node.js | Rust |
| **設定ファイル** | CLAUDE.md | AGENTS.md |
| **課金形態** | Claude Pro/Max または API従量課金 | ChatGPT Plus/Pro または API従量課金 |
| **日本語ドキュメント** | ✅ 公式が日本語対応 | ❌ GitHubリポジトリ（英語） |

## 搭載モデル

### Claude Codeのモデル

タスクに応じて`/model`コマンドでモデルを切り替え可能。

| モデル | 特徴 | 用途 |
|--------|------|------|
| **Sonnet 4.5** | バランス型（デフォルト） | 日常的なコーディング全般 |
| **Opus 4.5** | 最高性能 | 複雑な推論、アーキテクチャ設計 |
| **Haiku 4.5** | 高速・低コスト | 簡単なタスク、調査作業 |

Haiku 4.5はSonnet 4と同等のコーディング性能を持ちながら、3分の1のコストで2倍以上の速度を実現。

### Codex CLIのモデル

| モデル | 特徴 | 用途 |
|--------|------|------|
| **GPT-5.2-Codex** | 最新・最高性能 | サイバーセキュリティ、長時間タスク |
| **GPT-5.1-Codex-Max** | 長時間対応（デフォルト） | 大規模リファクタ、複雑な課題 |
| **GPT-5-Codex** | 安定版 | 通常のコーディング作業 |

GPT-5.2-CodexはOpenAI史上最高のサイバーセキュリティ能力。GPT-5.1-Codex-Maxは「コンパクション」技術により、数百万トークンにわたる長時間タスクを一貫して処理可能。

## セキュリティと権限モデル

### Claude Code

インタラクティブな権限モデルを採用：
- ファイルの書き込み・削除前に確認を求める
- シェルコマンド実行前に確認を求める
- 許可設定は`/permissions`で管理可能
- サンドボックスモードでさらに制限可能

### Codex CLI

デフォルトでサンドボックス環境で動作：
- ネットワークアクセスはデフォルトで無効
- 危険な操作は許可を求める
- セキュリティ設定はカスタマイズ可能

## 設計思想の違い

### Claude Code：「考えてから動く」アーキテクト

Claude CodeはUnix哲学に深く根ざしている。「一つのことをうまくやる」「すべての出力は他のプログラムへの入力になり得る」という思想。

#### プロジェクト全体の「メンタルマップ」構築

単にコードを生成するのではなく、ファイル間の依存関係や呼び出し構造をインデックス化し、「この変更がプロジェクト全体のどこに影響するか」を理解してから作業を始める。

これは単なるキーワード検索（grep）とは根本的に異なる。コードの**意味的なつながり**を理解している。

#### Plan Mode：思考と実行の分離

コードを書き始める前に、「何をどの順番でやるか」という計画を立てて提示する。

- 間違った方向に進む前に軌道修正できる
- 複雑なタスクを検証可能な小さなステップに分解
- AIが「なぜその変更を行うのか」を説明してくれる

#### 指示への忠実さと「反論する力」

AIツールには「追従問題（Sycophancy）」という課題がある。ユーザーの誤った指示にも「おっしゃる通りです」と従ってしまう現象。

Claude Codeは、CLAUDE.mdに定義されたルールに違反する指示を出されると、**異議を唱える傾向**がある。盲目的に従わない。

これは、レガシーコードの保守や、厳格な品質基準が求められるプロジェクトで重要。

### Codex CLI：「まず動く」実行者

「バイブコーディング（Vibe Coding）」という開発スタイルを牽引。細かい指示よりも「こんな感じで」という意図（Vibe）を汲み取って、AIが実装の詳細を決める。

#### Codexの技術的な強み

公平に言えば、Codex CLIには明確な強みがある：

- **GPT-5-Codex**は、実際のPull Requestデータを使った強化学習で訓練されており、「エンジニアのように振る舞う」ことに特化
- 特に**リファクタリング**において、既存の構造を壊さずに修正を加える能力が高い
- バックエンドの論理構築において、Production-readyなコードを書く傾向

## Claude Codeを推奨する理由

### 1. 日本語対応の質が高い

Claude Codeは、日本語での対話が自然。技術的なニュアンスや、日本の開発現場特有の言い回し（「よしなにやって」「バグってるかも」「いい感じにして」）も比較的正確に汲み取る。

Codex CLIは、英語圏のデータで強化学習されているため、「思考と言語のデフォルトが英語」。日本語でプロンプトを入力しても、コメントや説明が英語で返ってくることが多い。

### 2. 日本のコミュニティが圧倒的に強い

Zennにおいて、Claude Codeに関する記事は1,700件以上（2025年12月18日時点）あります。

これは単なるニュース紹介ではない。「仕様駆動開発への応用」「サブエージェントの検証」「Hooksを使った通知システム構築」といった、**実践的かつ高度な技術検証記事**が多数を占める。

コミュニティ発の電子書籍も複数出版されており、日本のエンジニアがClaude Codeを「実験的なツール」ではなく「実務のための主要ツール」として捉えている証拠。

**困ったときに日本語で情報を探せる**というのは、大きなメリット。

### 3. 深いコードベース認識

ユーザーが明示的にファイルを指定しなくても、エージェント自らがプロジェクトを探索し、依存関係を把握する。「この関数を直して」と言うだけで、該当ファイルを探し出し、関連する箇所も含めて修正できる。

### 4. 計画性と説明能力

「なぜその変更を行うのか」を説明してくれる能力は、学習にも役立つ。

AI駆動開発を始めたばかりの段階では、AIがどういう判断をしているのかを理解することが重要。Claude Codeは、その思考プロセスを見せてくれる。

### 5. 誤った指示に盲従しない

追従問題（Sycophancy）への耐性。レガシーコード保守や品質基準の厳しいプロジェクトで重要な特性。

## Codexが向いているケース

### 既存の契約を活かしたい

- ChatGPT Plus/Proを既に契約している
- 追加費用なしで使える

### 英語ベースの開発

- 英語でのやり取りに抵抗がない
- 英語圏のチーム・プロジェクト
- 英語で公式ドキュメントを読むことに抵抗がない

### 長時間の複雑なタスクが多い

- GPT-5.1-Codex-Maxの「コンパクション」技術で数百万トークンにわたる長時間タスクを処理
- 大規模リファクタリングや複雑な課題に対応

### GPT-5-Codexの実装力が必要

- 実際のPull Requestデータで強化学習
- リファクタリングで既存構造を壊さない能力
- バックエンドの論理構築が得意

### コードレビュー中心の使い方

- `/review` コマンドが強力
- レビュー目的なら部分的に使う価値あり

## 機能比較

### コンテキスト設定ファイル

どちらもプロジェクト固有のルールをAIに教えるための設定ファイルをサポート。

| Claude Code | Codex CLI |
|-------------|-----------|
| `CLAUDE.md` | `AGENTS.md` |

書く内容の例：
- ビルド・テストコマンド
- コーディング規約（命名規則、スタイル）
- アーキテクチャの概要
- 「日本語で回答して」などの指示

> `AGENTS.md`は他のツール（Cursorなど）でも採用が進んでおり、業界標準になりつつある。

### MCP（Model Context Protocol）

MCPは、AIエージェントと外部ツール（DB、Slack、Figmaなど）を接続するための標準規格。Anthropicが開発し、Linux Foundationに寄贈。

Claude CodeはMCPの**生みの親**であり、ネイティブに統合されている。興味深いことに、Codex CLIもこのMCPを採用した。これにより、ツール連携の部分では両者の差がなくなりつつある。

### Git連携

| 機能 | Claude Code | Codex CLI |
|------|-------------|-----------|
| コミット・PR作成 | ◎ 得意 | ○ |
| コードレビュー | ○ | ◎ /reviewコマンド |

Claude Codeは「作成」に強く、Codex CLIは「レビュー」に強いという傾向。

### サブエージェント

Claude Codeのサブエージェント機能は、複雑なタスクを分解して処理するのに優れている。メインの会話とは独立したコンテキストで作業させ、結果だけを持ち帰らせることができる。

## 推奨される使い分け

- **初心者はドキュメントが充実したClaude Codeから始める**のがベスト
- 慣れてきたら両ツールを使い分ける
- **普段はClaude Code、難しい課題だけCodex CLI**という使い分けも効果的
- カスタマイズ性を重視するならClaude Code
- 適度にコストを抑えたいならClaude Code（Max 5xという中間プランがある）

## 執筆時のポイント

### Claude Code推奨の根拠

1. **日本語対応** - ニュアンスが通じる、英語がデフォルトにならない
2. **コミュニティ** - 日本語情報が豊富、困ったときに探せる
3. **計画性** - Plan Modeで思考が見える、学習にも役立つ
4. **コード理解** - 意味論的な把握、grepとは違う
5. **品質維持** - 追従問題への耐性、誤った指示に盲従しない

### Codexを紹介する場面

1. **既存契約** - ChatGPT Plus/Proユーザー
2. **レビュー用途** - /reviewコマンドの活用
3. **リファクタリング** - 既存構造を壊さない（PRデータで学習）
4. **セカンドオピニオン** - 別視点での検証

### 伝え方のポイント

- 「どちらが優れているか」ではなく「誰に向いているか」
- 日本の開発者にはClaude Codeが入りやすい
- Codexも特定用途では価値がある
- 併用という選択肢もある
- ツールを使いこなせるか、困ったときに解決策を見つけられるかが重要
