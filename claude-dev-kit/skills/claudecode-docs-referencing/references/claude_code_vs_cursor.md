# Claude Code vs Cursor：使い分けガイド

Claude Codeをメインに、Cursorをサブ的に使う場合の参照資料。

**結論: Claude Codeをメインに使いつつ、必要に応じてCursorを併用するのがおすすめ**

---

## 本質的な違い

| 観点 | Claude Code | Cursor |
|------|-------------|--------|
| **形態** | CLIツール（ターミナルベース） | AI統合IDE（VS Codeフォーク） |
| **導入スタイル** | 既存環境にエージェントを追加 | IDE丸ごとAIファーストに刷新 |
| **設計思想** | 業務の委譲（Delegation） | 能力の拡張（Augmentation） |
| **ユーザーの役割** | マネージャー（監督者） | ドライバー（操縦者） |
| **AIの役割** | 独立したエンジニア | 自分の手の延長 |
| **モデル** | Claude特化（Sonnet / Opus） | マルチベンダー（OpenAI / Claude / Gemini） |
| **特徴的な機能** | サブエージェント、カスタムコマンド | リアルタイム補完、Composer |
| **比喩** | 優秀な自律的部下 | アイアンマンのスーツ |

### なぜこの違いが生まれるか

**Cursor**は「人間の能力拡張（Augmentation）」を核とし、開発者がフロー状態を維持しながら超高速でコーディングを行う体験を提供する。これが「Vibe Coding」と呼ばれる新たな体験。

**Claude Code**は「業務の委譲（Delegation）」を核とし、人間がマネージャー、AIがエンジニアとして振る舞う階層的なワークフローを構築する。AIは単なる入力支援ではなく、調査、計画、実行、検証というエンジニアリングプロセス全体を担う主体。

### 操作スタイルの違い

**Claude Code（Human-on-the-loop）**
- 人間は監督者として、計画の承認や最終成果物のレビューを行う
- 指示を出して数分〜数十分待つ
- 「後輩エンジニアに仕事を任せる」感覚

**Cursor（Human-in-the-loop / Agent mode）**
- 従来は人間がハンドルを握り、AIの提案を逐次確認して採用/拒否を判断するスタイル
- 2026年1月現在、CursorもAgent modeを備えており、複数ファイルにまたがる自律的な作業が可能
- 「Cursorは人間が常にハンドルを握る」という以前の説明は、現在では当てはまらなくなっている
- 「ペアプログラマーが横からささやく」感覚から、「自律的なアシスタント」にも対応

## Claude Codeをメインにする理由

### サブスクリプションの使い放題感

Claude Pro / Maxを契約している方にとって、Claude Codeはすでに使える状態になっている。サブスクリプション内では**5時間の枠内でリミットまで使い放題**で、枠がリセットされたらまた使い始められる。

Cursorの場合、月あたりのプレミアムリクエスト制限があり、MAXモードでモデルを使うとすぐにレートリミットに達してしまうという声も。ガンガン使いたい開発者にとっては、Claude Codeのほうが心理的な負担が少ない。

### エディタを選ばない自由さ

Claude CodeはCLIベースなので、どんなエディタとも組み合わせられる。VS Code、JetBrains、Vim、Emacs、さらにはCursor自体のターミナルでもClaude Codeは動作する。「IDEに縛られない」という自由度は、Claude Codeならではの強み。

### サブエージェントとカスタムコマンド

Claude Code独自の機能として**サブエージェント**がある。これは複数の専門家AIを独立して活用できる機能で、コーディング規約チェッカーやセキュリティチェッカーなど、プロジェクト固有の専門知識を持たせることができる。

また、**`/code-review`** や **`/security-review`** といった組み込みコマンドも便利。PRに対して自動的にコードレビューを実行したり、セキュリティ観点でのチェックを行える。

### コンテキスト管理の強み

Claude Codeのアプローチは、RAGによる情報の「つまみ食い」とは対照的。プロンプトキャッシュ技術を駆使し、プロジェクトのディレクトリ構造、主要なファイル、コーディング規約（CLAUDE.md）、過去の会話履歴などを、最大200kトークンのコンテキストウィンドウに丸ごと保持し続ける。

これにより、ファイル間の隠れた依存関係、プロジェクト全体のアーキテクチャ、暗黙のルールを深く理解できる。RAGでは検索漏れによって見過ごされるような、「明示的には関連していないが、論理的に影響を受ける箇所」も、広範なコンテキスト視野によって捉えることが可能。

- **最大200K〜1Mトークン**のコンテキストウィンドウ
- **CLAUDE.md**でプロジェクト固有のコンテキストを永続化
- **サブエージェント**でコンテキストを分散
- **Compressor機能**でコンテキスト制限に近づくと会話を要約

### 自律的な探索・実行能力

Claude Codeは単にテキストを生成するだけでなく、実際の「行動」を起こす能力を持つ。`ls`でファイル構造を把握し、`grep`で文字列を検索し、ファイルを読み書きし、テストコマンドを実行し、Gitでコミットを作成する。

特にMCP（Model Context Protocol）への対応により、GitHub、Jira、Slack、データベースなど、ローカル環境外の外部リソースとも接続し、情報を取得・操作することが可能。

### 得意なタスク

| タスク | なぜClaude Codeが強いか |
|--------|------------------------|
| **大規模レガシーコードの調査・修正** | 自律的にgrep/findで探索、200kトークンで複雑なロジックを把握。ユーザーが関連ファイルを開く必要がない |
| **プロジェクト全体のリファクタリング** | ファイル操作＋編集を一括処理、ビルド→修正のループを自動実行。変更後に自律的にビルドコマンドを実行し、エラーがあれば修正 |
| **End-to-End実装（DBからUIまで）** | Plan Modeで計画立案、レイヤーを跨いで整合性を保つ。コンテキストを保持したまま作業を進める |
| **TDDループの自動化** | テスト実行→失敗ログ読み取り→修正→再テストを自律的に繰り返す。All Greenになるまで粘り強く作業 |
| **Git操作・PR作成** | CLIツールとの親和性、git/ghコマンドを直接実行。コミットメッセージ生成からPR作成まで自動化 |
| **ドキュメントとコードの整合性確認** | 大量テキストを同時比較、乖離を検出して一括更新。人間には退屈で広範囲な確認作業をこなす |
| **環境構築・トラブルシューティング** | コマンドライン操作が主、エラー解析してインフラ問題を解決。環境構築は依存関係のインストールや環境変数の設定など |

## Cursorをサブで使う場面

### なぜCursorが向いているか

CursorのUXは、ユーザーが常にエディタの前に座り、AIの提案を逐次確認し、採用または拒否を判断することを前提としている。現在開いているファイル、カーソルの位置、直前に閲覧したファイル、選択中のコードブロックといった「暗黙のコンテキスト」を自動的に取り込む。

「Cursor Tab」機能は、カーソルの動きと直前の変更履歴を分析し、次の数行から数十行のコード変更を予測してゴーストテキストとして表示する。単なる単語補完ではなく、文脈を理解したロジックの生成。

### Cursorが向いているタスク

| タスク | なぜCursorが向いているか |
|--------|------------------------|
| **UI/CSSの視覚的調整** | 「書いては確認する」サイクルの連続。インライン編集で対象のJSXタグを選択し、自然言語で指示。保存で即座にホットリロード |
| **リネーム・小規模リファクタ** | LSP統合でマルチファイル編集、Diffビューで変更箇所を目視確認し「Apply」ボタン一つで確定 |
| **TypeScript型エラー修正** | 赤波線が出ている箇所にカーソルを合わせると、エラーメッセージとコードの文脈を同時に読み取り修正 |
| **単一ファイルのテスト追加** | Tab補完が対象コードを読み取り、テストの中身を次々と予測。タブキー連打でテストの骨子が完成 |
| **ドキュメントコメント追加** | 関数ヘッダの上で「/**」とタイプするか、コードを選択してコマンド実行でAIがロジックを解析してコメント生成 |
| **正規表現の生成・検証** | チャットパネルで生成された正規表現に対して追加注文を出し、すぐにコード内で試せる |
| **ライブラリの使い方確認** | @Web検索統合で最新のドキュメントやAPI仕様を検索し、現在のコードの文脈に合わせた実装コードを生成 |
| **特定エラーのデバッグ** | IDE内のターミナル出力をコンテキストとして認識、「Add to Chat」でエラーログを取り込み関連するソースコードを特定 |

### タスク規模で判断

| 規模 | 目安 | 推奨 | 理由 |
|------|------|------|------|
| XS（数行） | 〜1分 | Cursor | Tab補完で瞬時に完了 |
| S（1関数） | 1-5分 | Cursor | Cmd+Kで即座にdiff確認 |
| M（1ファイル大幅変更） | 5-15分 | どちらでも | 好みとコンテキスト次第 |
| L（複数ファイル） | 15-60分 | Claude Code | 自律的な計画・実行が効率的 |
| XL（システム全体） | 1時間以上 | Claude Code | 長時間の自律作業が可能 |

## ハイブリッド戦略

### 開発フェーズ別の使い分け

| フェーズ | ツール | 理由 |
|----------|--------|------|
| **要件定義・設計** | Claude Code | 抽象的な要件から設計案を生成。既存のモノリスのコードや共通ライブラリを読み込み、矛盾のないAPI定義やDBスキーマの設計案を提示 |
| **スキャフォールディング** | Claude Code | ディレクトリ構造の作成、設定ファイルの生成、DBマイグレーション、基本的なCRUD APIの実装といった「大量の定型作業」を一括で行う |
| **ビジネスロジック・UI調整** | Cursor | 「この計算のエッジケースはどうする？」「ボタンの色をもう少し明るく」といった微調整が発生。ComposerやCmd+Kが圧倒的に速い |
| **結合テスト・デバッグ** | 使い分け | 特定コンポーネントのバグ（原因明確）→Cursor、原因不明のシステムエラー→Claude Codeに「探偵役」をさせる |
| **ドキュメント・PR作成** | Claude Code | README.mdの更新、API仕様書の生成、GitコミットとPR作成まで自動化 |

### 併用のパターン

- **CursorのターミナルでClaude Codeを動かす**ことも可能
- 日常のコーディング→Cursor、大きなタスク→Claude Code
- 探索・計画→Claude Code、実装の仕上げ→Cursor
- 両方使い分けている開発者が多い

### コスト面の考慮

両方使う場合、コスト面は考慮が必要。Claude Pro / Maxに加えてCursor Proも契約すると、月額料金がそれなりにかかる。

お財布に余裕があれば両方契約して使い分けるのがベストだが、**まずはClaude Codeだけでも十分に開発効率は上がる**ので、Claude Codeをしっかり使いこなすことをおすすめ。

## 執筆時のポイント

### Claude Codeを推奨する根拠

1. **自律的な探索・計画・実行** - どこにバグがあるかわからなくても任せられる。ユーザーがファイルを開く必要がない
2. **広大なコンテキスト** - RAGの検索漏れがない。「明示的には関連していないが影響を受ける箇所」も捉える
3. **CLIツールとの親和性** - Git、テスト、ビルドまで一気通貫。MCPで外部ツールとも連携
4. **委譲のワークフロー** - 監督者として効率的に仕事を回せる。調査→計画→実行→検証を任せられる

### Cursorをサブで使う場面

1. **UI/CSSの微調整** - 視覚的フィードバックが必要。ホットリロードとの相性が良い
2. **小規模な変更** - Tab補完の速さが活きる。タブキー連打で完成
3. **特定ファイルのエラー修正** - エディタ上で完結。赤波線から直接AIに依頼
4. **対話的な試行錯誤** - 数秒単位のやり取り。「暗黙のコンテキスト」を活用

### 「どちらか一方」ではなく「使い分け」

- 両方使う開発者が多い
- フェーズや規模で切り替える
- Cursor内でClaude Codeも動く
- 微細なロジックやUIの挙動にこだわる時→Cursor、大規模な変更や退屈な作業→Claude Codeに委譲
