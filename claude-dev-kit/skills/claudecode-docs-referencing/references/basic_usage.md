# 03. 基本的な使い方

## Claude Code の起動と終了

### 起動
```bash
# プロジェクトディレクトリに移動
cd your-project

# Claude Code を起動
claude
```

### 終了
```bash
# 通常の終了
/exit

# または
Ctrl+C を2回
```

**Tips**: `Ctrl+C` を2回押すと即座に終了できる

## コマンドの種類

Claude Code のコマンドは **2種類** に分かれます:

1. **シェルコマンド**: ターミナルで直接実行（`claude` から始まる）
   - 起動、終了、会話の再開など
2. **スラッシュコマンド**: Claude Code の対話モード内で使用（`/` から始まる）
   - 会話履歴のクリア、ヘルプ表示など

## 基本的な対話方法

### 質問する
Claude に質問や指示を自然言語で伝えます:

```
> このプロジェクトの構造を教えて

> README.md を作成して

> このコードのバグを見つけて修正して
```

### ファイルを参照させる
```
> src/app.js の内容を確認して説明して

> package.json を読んで、依存関係を教えて
```

## よく使うツール

Claude は自動的に以下のツールを使用します:

### Read - ファイルを読む
```
> config.json の内容を確認して
```

### Write - ファイルを作成
```
> index.html を作成して、シンプルなランディングページにして
```

### Edit - ファイルを編集
```
> app.js の関数名を分かりやすく変更して
```

### Bash - コマンドを実行
```
> 依存関係をインストールして

> テストを実行して結果を教えて
```

### Grep - コードを検索
```
> このプロジェクト内で "TODO" コメントを全て見つけて
```

### Glob - ファイルパターンで検索
```
> すべての TypeScript ファイルを見つけてリストアップして
```

## 権限システム

Claude がツールを使用する際、権限を求められることがあります。

### 権限の種類
- **Allow(許可)**: 今回のみ許可
- **Allow Always(常に許可)**: 同じツールを常に許可
- **Deny(拒否)**: 今回は拒否
- **Deny Always(常に拒否)**: 同じツールを常に拒否

### 権限の管理
```bash
# 権限設定を確認・変更
/permissions
```

設定例:
```json
{
  "allow": [
    "Bash(npm install)",
    "Read(~/.zshrc)"
  ],
  "deny": [
    "Bash(rm -rf *)"
  ]
}
```

## 承認モード

Claude Code にはファイル編集時の承認方法を制御する3つのモードがあります。

### モードの切り替え

`shift+tab` キーを押すと、以下のサイクルでモードが切り替わります:

1. **default mode** - デフォルトのモード。編集ごとに確認が表示される
2. **accept edits on** - 自動承認モード。今後のファイル編集は自動的に承認される
3. **plan mode on** - 計画モード。ファイルに変更を行う前に計画を立て、ユーザーの承認を求める

### 編集の確認画面

ファイル作成・編集時には確認画面が表示されます:

```
Do you want to create main.js?
❯ 1. Yes
  2. Yes, allow all edits during this session (shift+tab)
  3. Type here to tell Claude what to do differently
```

- **Yes**: 今回のみ許可
- **Yes, allow all edits during this session**: 以降の編集もすべて自動承認（accept edits on モードに切り替え）
- **Type here...**: Claude に別の指示を出す

### モードの表示

現在のモードはプロンプト下部に表示されます:

```bash
⏵⏵ accept edits on (shift+tab to cycle)
```

```bash
⏸ plan mode on (shift+tab to cycle)
```

### 差分表示

コード変更時は差分形式で表示されます:

```diff
⏺ Update(main.js)
  ⎿  Updated main.js with 4 additions
       1    console.log("Hello");
       2 +
       3 +  function helloWorld() {
       4 +    console.log("Hello, World!");
       5 +  }
```

`+` マークが追加された行を示します。

## ヘッドレスモード（-p オプション）

対話モードに入らず、一度限りのタスクだけ実行したい場合に使用する「ヘッドレスモード」（非対話モード）。

### 基本的な使い方

```bash
claude -p "README.mdを読んで、概要を説明して"
```

`-p`（または `--print`）オプションを使うと、プロンプトを処理し、結果を標準出力に出力して終了する。
スクリプトからの呼び出しやパイプ連携に最適。

### モデルを指定する

```bash
claude -p "コードをレビューして" --model opus
```

指定できるモデル名: `opus`, `sonnet` など。

### 許可するツールを制限する

```bash
claude -p "コードを分析して問題点を報告して" --allowedTools "Read,Grep,Glob"
```

この例では**ファイルの読み取りと検索のみを許可**し、書き込みやコマンド実行は禁止される。

### 出力形式の指定

#### テキスト形式（デフォルト）

```bash
claude -p "バグを見つけて報告して" --output-format text
```

人間が読みやすいプレーンテキスト形式で出力。

#### JSON形式

```bash
claude -p "コードの問題点を分析して" --output-format json
```

応答内容に加えてメタデータも含まれる:

```json
{
  "type": "result",
  "subtype": "success",
  "result": "分析結果のテキスト...",
  "session_id": "abc123",
  "total_cost_usd": 0.003
}
```

### カスタムコマンドの呼び出し

スラッシュコマンドもヘッドレスモードで実行可能:

```bash
claude -p "/create-review src/main.ts"
```

引数はコマンド名の後にスペース区切りで指定。コマンドファイル内では `$ARGUMENTS` や `$1`, `$2` として参照可能。

### 権限確認をスキップする

```bash
claude -p "/my-command" --dangerously-skip-permissions
```

**注意**: このオプションは危険。すべてのツール実行が自動承認されるため、信頼できるコマンドでのみ使用すること。`--allowedTools` との併用を推奨。

### パイプ処理との組み合わせ

標準入力からデータを受け取り、標準出力に結果を出力できる:

```bash
# ファイル内容を分析
cat error.log | claude -p "このエラーログの原因を分析して"

# コマンド出力を分析
npm run test 2>&1 | claude -p "テスト結果を要約して"

# Git差分をレビュー
git diff | claude -p "この変更内容をレビューして"
```

### その他のオプション

| オプション | 説明 |
|-----------|------|
| `--max-turns <n>` | エージェントループのターン数上限を設定 |
| `--continue`, `-c` | 直前の会話を継続 |
| `--resume <session-id>` | 特定のセッションを再開 |
| `--verbose` | 詳細ログを出力（デバッグ用） |
| `--disallowedTools` | 禁止するツールを指定 |

### 会話を継続する

```bash
claude -p "さっきのコードにテストを追加して" --continue
```

### 注意点

- **コンテキストの独立性**: 各呼び出しは独立したセッション。前回の結果を引き継ぐには `--continue` や `--resume` を使用
- **コスト**: ヘッドレスモードでも通常どおりトークンが消費される。大量のファイル分析や頻繁な実行時はコストに注意
- **コスト削減のコツ**: 必要なファイルだけを対象にする、`--allowedTools` で読み取り専用に制限する

## セッションの管理

### セッションとは

Claude Code における**セッション**とは、一連の対話のまとまりを指す。セッション内の会話履歴は「コンテキスト」として保持され、過去の会話を踏まえた対応が可能になる。

各セッションには固有の**セッションID**が割り当てられており、後から特定のセッションを再開できる。

### 新しいセッションを開始
```bash
claude
```

**注意**: 過去のセッション情報は自動的には引き継がれない。続きをやりたい場合は `--continue` オプションを使用。

### 前回のセッションを続ける
```bash
claude --continue
# または
claude -c
```

**現在のディレクトリで最後に行ったセッション**が読み込まれる。

### 過去のセッションから選択
```bash
# 対話モード内で
/resume
```

実行すると過去の会話一覧が表示され、再開したい会話を選択できる:

```
Resume

❯ README.mdを読んで、概要を説明して
  14 seconds ago · 4 messages · main

↓ テストのエラーを修正して
  1 minute ago · 2 messages · main

A to show all projects · P to preview · R to rename · / to search · Esc to cancel
```

### セッション名の変更
```bash
/rename 新しいセッション名
```

セッション名を変更すると `/resume` の一覧で識別しやすくなる。

### 特定のセッションIDを指定して再開
```bash
claude --resume abc123def456
```

セッションIDは `/resume` コマンドの一覧画面で確認可能。頻繁に参照するセッションがある場合はメモしておくと便利。

## メッセージの編集と再送

### メッセージを編集
- 最後のメッセージを編集したい場合、上矢印キーで履歴を表示
- 編集して Enter で再送信

### 複数行のメッセージ
改行を入れる方法:
1. `\` + Enter
2. Shift + Enter (ターミナル設定による)
3. Option + Enter (Mac)

## コンテキストの管理

### コンテキストウィンドウとは

**コンテキストウィンドウ**はClaudeが一度に処理できるテキスト量の上限。以下の要素がコンテキストを消費する:

- **会話履歴**: やり取りの全記録
- **読み込んだファイル**: `@`記法で参照したコード
- **システムプロンプト**: CLAUDE.mdや設定ファイル
- **MCPからの情報**: 外部連携データ

上限を超えると、古い情報から自動的に削除される。

- 大きなファイルを読み込んだ後

### コンテキストのクリア（/clear）

```bash
/clear
```

現在のセッションの会話履歴をすべて削除。CLAUDE.mdや`.claude/rules/`などのプロジェクト設定は自動的に再読み込みされる。

**使うべき4つのタイミング**:

1. **タスクが完了し、別のタスクに移るとき** - 機能Aの実装が終わり、まったく関係のない機能Bに取りかかる場合

2. **話題を大きく変えたいとき** - 前の会話の文脈が意図しない方向に引っ張る可能性

3. **会話を引き継がなくても良い場合** - リファクタリングなど、フレッシュな目線で行いたい作業

4. **コンテキストが混乱している場合** - 回答が矛盾したり、過去の情報に引きずられている場合

### 圧縮（/compact）

```bash
/compact
```

過去の会話を要約してトークン数を削減。**会話内容が完全に消えるわけではない** - 要約された形で残るため、文脈を維持したまま会話を続けられる。

**トピックを指定した圧縮**:

```bash
/compact APIの仕様についてフォーカスして
```

| 場面 | コマンド例 |
|------|-----------|
| 設計議論を保持したい | `/compact アーキテクチャの決定事項にフォーカスして` |
| コードの変更履歴を残したい | `/compact 実装した機能の詳細にフォーカスして` |
| エラー解決の経緯を残したい | `/compact バグの原因と修正内容にフォーカスして` |

**自動コンパクト機能**: コンテキストウィンドウが満杯に近づくと自動的にコンパクトが実行される。ただし、特定トピックを優先するなどの細かな制御はできないため、重要な情報を確実に残したい場合は手動で実行する。

### /clear と /compact の使い分け

| コマンド | 動作 | 情報の保持 |
|---------|------|-----------|
| `/clear` | 完全にリセット | 何も残らない |
| `/compact` | 要約して圧縮 | 重要な情報は残る |

| 状況 | 推奨コマンド |
|-----|------------|
| タスクが完全に終わった | `/clear` |
| 同じタスクを継続したい | `/compact` |
| コンテキストが混乱している | `/clear` |
| 重要な情報は残したい | `/compact` |

### コンテキスト汚染の影響

`/clear`を適切なタイミングで使わないと発生する問題:

| 問題 | 具体例 |
|------|--------|
| **判断の混乱** | 過去のタスクの情報を参照し、現在のタスクに無関係な提案をする |
| **トークン消費の増加** | 不要な会話履歴がコンテキストを圧迫し、コストが増える |
| **応答速度の低下** | 処理すべき情報量が増え、応答が遅くなる |
| **矛盾した回答** | 過去の回答と現在の回答が矛盾する |

## ファイル操作のベストプラクティス

### 1. 具体的な指示を出す
❌ 悪い例:
```
> いい感じのUIにして
```

✅ 良い例:
```
> ヘッダーにロゴを左寄せ、ナビゲーションメニューを右寄せで配置して。
  レスポンシブ対応で、モバイルではハンバーガーメニューにして
```

### 2. 段階的に作業を進める
複雑なタスクは分割して依頼:

```
1回目: > 基本的なHTML構造を作成して
2回目: > CSS でスタイリングを追加して
3回目: > JavaScript で動的な機能を追加して
```

### 3. 確認しながら進める
```
> まず、実装方針を教えて
(方針を確認)
> OK、その方針で実装して
```

## 画像を使った開発

Claude は画像を読み取ることができます。

### 画像のアップロード方法
1. 画像を Claude Code ウィンドウにドラッグ&ドロップ
2. 画像をコピーして貼り付け（macOS/Linux: `Ctrl+V`, Windows: `Alt+V`）
3. パスを指定: `この画像を分析して: /path/to/image.png`

### 使用例
```
> このデザインモックアップを React コンポーネントとして実装して
(デザイン画像をアップロード)

> このエラーのスクリーンショットを見て、原因を調査して
(エラー画面をアップロード)

> このフローチャートを Python のコードに変換して
(フローチャート画像をアップロード)
```

## 拡張思考モード

複雑な問題には、Claude により深く考えさせることができます:

```
> ultrathink システム全体の設計を見直して
```

**重要**: `ultrathink` キーワードを使用した場合のみ、思考予算（最大31,999トークン）が割り当てられます。

`think`, `think harder`, `think more` などの表現は通常のプロンプト指示として処理され、思考予算は割り当てられません。

グローバルに拡張思考を有効化する場合は `/config` から設定可能です。

## コスト管理のコツ

### 1. 短く具体的な指示
- トークン消費を抑えられる
- より正確な結果が得られる

### 2. 定期的にコンテキストをクリア
```bash
/clear
```

### 3. セッションを分ける
新しいタスクは新しいセッションで:
```bash
claude  # 新規セッション
```

### 4. 使用量を確認
```bash
npx ccusage@latest
```

## トラブルシューティング

### 応答が遅い/止まる
- 30-60秒待つ(複雑なタスクは時間がかかる)
- `/status` でステータスを確認
- Ctrl+C で中断して再試行

### エラーが頻発
```bash
# 接続を確認
/status

# 再ログイン
/logout
/login
```

### 期待と違う動作をする
- より具体的な指示を出す
- `/clear` でコンテキストをリセット
- 例を示す
