# 14. ベストプラクティス

## 効率的な Claude Code の使い方

### 1. 具体的で明確な指示を出す

❌ **悪い例**:
```
> いい感じに直して
> バグを修正して
> もっと良くして
```

✅ **良い例**:
```
> ユーザー認証部分で、空のメールアドレスが送信された時のバリデーションを追加して

> ヘッダーコンポーネントのモバイル表示で、ナビゲーションメニューがはみ出す問題を修正して

> データベースクエリのN+1問題を解決するため、eager loadingを実装して
```

### 2. 段階的にタスクを進める

複雑なタスクは小さく分割:

```
# ステップ1
> まず、新しい API エンドポイントの設計を提案して

# ステップ2(設計を確認後)
> その設計で実装して

# ステップ3
> エラーハンドリングを追加して

# ステップ4
> テストを作成して
```

### 3. コンテキストを適切に管理

#### 定期的にクリア
```bash
# 新しいタスクを開始する前
/clear
```

#### 圧縮を活用
```bash
# 長い会話履歴を要約
/compact
```

#### 必要な情報のみ共有
❌ プロジェクト全体を一度に読み込ませる
✅ 関連するファイルのみを指定

### 4. CLAUDE.md を活用する

プロジェクト固有の情報を記録:

```markdown
## コーディング規約
- インデント: 2スペース
- 命名: キャメルケース
- コメント: JSDoc形式

## よくあるタスク
- テスト実行: `npm test`
- ビルド: `npm run build`
- デプロイ: `npm run deploy`

## 注意事項
- API キーは環境変数から取得
- エラーログは必ず記録
- ユーザー入力は必ず検証
```

### 5. 適切なモデルを選択

タスクの複雑さに応じてモデルを使い分け:

- **Sonnet 4.5** (推奨): ほとんどのタスク
- **Opus 4.5**: 複雑な設計、アーキテクチャ決定
- **Haiku**: 簡単な修正、フォーマット、高速処理

```bash
/model
```

## スクリーンショット入力の活用

Claude Codeはマルチモーダル対応のため、**スクリーンショットを入力として受け付ける**。言葉で説明しにくいUIの問題も、視覚的に伝えることが可能。

### スクリーンショットの撮り方

**Mac**:
```
Cmd + Shift + 4
```
範囲選択してクリップボードに保存。

**Windows**:
```
Win + Shift + S
```
Snipping Toolで範囲選択。

### Claude Codeへの貼り付け

- **Mac**: `Cmd + V`（または `Ctrl + V`）
- **Windows**: `Ctrl + V`

貼り付けると `[Image #1]` と表示される:
```bash
> [Image #1]
```

### 活用シーン

#### UIバグの修正
```
[Image #1]
このボタンのテキストが切れてしまっています。修正してください。
```

#### デザインカンプの実装
```
[Image #1]
このデザインと同じレイアウトを実装してください。
Tailwind CSSを使用しています。
```

#### エラー画面の解決
```
[Image #1]
このエラーを解決してください。
```

### 効果的な指示の出し方

**1. 具体的な説明を添える**
```
[Image #1]
赤枠で囲った部分のマージンを20pxに変更してください。
```

**2. 期待する結果を明示する（Before/After）**
```
[Image #1]
現在：テキストが1行で表示されている
期待：3行で表示し、はみ出す場合は省略記号（...）を表示
```

**3. 技術スタックを伝える**
```
[Image #1]
このレイアウトを修正してください。
技術スタック：Next.js, Tailwind CSS
```

### 注意点

**コンテキストの消費**:
- 大きな画像はコンテキストを多く消費
- 画面全体ではなく、**必要な部分だけ切り取る**
- ピンポイントで画像を渡すことで修正箇所が特定しやすくなる

**著作権への配慮**:
- 他サイトのデザイン参考時は著作権に注意
- ロゴやアイコンをそのまま使用しない
- レイアウトパターンの参考にとどめる

## コスト最適化

### 1. トークンを節約する

#### プロンプトを簡潔に
❌ 「このアプリケーションの全てのファイルを読んで、どこに問題があるか分析して...」
✅ 「src/auth.js のログイン関数でエラーが出る。原因を調査して」

#### 不要なコンテキストを削除
```bash
/clear  # 不要な履歴を削除
/context  # コンテキスト使用量を確認
```

### 2. セッションを分ける

異なるタスクは別セッション:

```bash
# タスク1: バグ修正
claude
> バグを修正
exit

# タスク2: 新機能(新しいセッション)
claude
> 新機能を実装
```

### 3. 使用量を監視

```bash
# 定期的に確認
npx ccusage@latest
```

月の途中で予算を超えそうな場合は使用頻度を調整。

## ワークフロー最適化

### 1. IDE との連携

効率的なショートカット:
- `Esc` + `Esc` - 会話と変更を巻き戻す
- `Shift+Tab` または `Alt+M` - パーミッションモード切り替え
- `Option+P` (Mac) / `Alt+P` (Win) - モデル切り替え
- `Ctrl+O` - 詳細出力（思考モード表示）切り替え

詳細は **06_ide_integration.md** 参照。

### 2. カスタムコマンドを活用

頻繁に行う操作をコマンド化:

```markdown
.claude/commands/
├── commit-msg.md    # コミットメッセージ生成
├── review.md        # コードレビュー
└── test-gen.md      # テスト生成
```

詳細は **07_custom_commands.md** 参照。

### 3. サブエージェントを使い分け

専門的なタスクはサブエージェントに委任:

```
> code-reviewer でセキュリティをチェック
> debugger でこのエラーを調査
> test-writer でテストを追加
```

詳細は **08_subagents.md** 参照。

### 4. フックで自動化

繰り返しのタスクはフックで自動化:

- ファイル保存時に自動フォーマット
- コミット前に自動テスト
- デプロイ前にビルドチェック

詳細は **09_hooks.md** 参照。

### 1. レビューを習慣化

```

> セキュリティ上の問題がないかチェックして

> パフォーマンスボトルネックを確認して
```

### 2. テストを自動生成

```
> この関数のユニットテストを作成して

```

### 3. ドキュメントを維持

```

```

## チーム開発のベストプラクティス

### 1. プロジェクト設定を共有

Git にコミット:
```bash
git add .claude/
git commit -m "Add Claude Code project configuration"
```

共有すべきもの:
- `CLAUDE.md` - プロジェクトコンテキスト
- `.claude/commands/` - チーム共通コマンド
- `.claude/agents/` - プロジェクト固有エージェント
- `.claude/settings.json` - プロジェクト設定

共有しないもの:
- `.claude/settings.local.json` - 個人設定

### 2. 一貫したコーディング規約

CLAUDE.md に明記:

```markdown
## コーディング規約
- TypeScript strict モード必須
- Prettier でフォーマット
- ESLint ルールに従う
- 関数は50行以内
- ネストは3段階まで
```

### 3. サブエージェントを標準化

チーム共通のサブエージェントを作成:

```
.claude/agents/
├── code-reviewer.md  # チーム標準のレビュー基準
├── test-writer.md    # テスト作成ガイドライン
└── documenter.md     # ドキュメント規約
```

## トラブルシューティングのヒント

### 期待と違う結果が出た場合

1. **より具体的に指示**
   ```
   > もっと詳しく: この関数は何をするべきか、どんな入力を受け取り、何を返すか
   ```

2. **例を示す**
   ```
   > こういう形式で出力して:
   (例を提示)
   ```

3. **段階的に確認**
   ```
   > まず方針を教えて
   (方針を確認)
   > OK、その方針で実装して
   ```

### Claude が混乱している場合

```bash
# コンテキストをリセット
/clear

# 新しいセッション
exit
claude
```

### パフォーマンスが遅い場合

1. コンテキストを減らす (`/clear`)
2. 高速なモデルに切り替え (`/model` → haiku)
3. タスクを分割

## セキュリティのベストプラクティス

### 1. 機密情報を共有しない

❌ API キー、パスワード、秘密鍵を直接入力
✅ 環境変数やシークレット管理ツールを使用

```
> .env ファイルから API_KEY を読み込んで使用
```

### 2. コード生成後は必ず確認

Claude が生成したコードを盲目的に信用せず、必ず:
- セキュリティリスクをチェック
- ロジックを理解
- テストを実行

### 3. 権限を適切に設定

```bash
/permissions

# 危険なコマンドは拒否
deny: Bash(rm -rf *), Bash(sudo *)
```

## 学習のヒント

### 1. Claude の思考を観察

拡張思考（Extended Thinking）を使って Claude の思考プロセスを学ぶ:

```
> ultrathink: このアーキテクチャの設計を考えて
```

**注意:**
- `ultrathink:` は1回のリクエストのみ思考を有効化
- `/config` でグローバルに思考モードを設定可能
- Sonnet 4.5 と Opus 4.5 はデフォルトで思考が有効

### 2. コードレビューで学ぶ

```
> このコードをレビューして、改善点を詳しく説明して
```

### 3. 段階的に複雑化

簡単なタスクから始めて、徐々に複雑なタスクに挑戦:

1. 単純なファイル作成
2. 既存コードの修正
3. 新機能の実装
4. アーキテクチャの設計

## まとめ

効率的な Claude Code 使用の5つのポイント:

1. **具体的な指示** - 曖昧さを避ける
2. **コンテキスト管理** - 必要な情報のみ共有
3. **自動化** - 繰り返しタスクはコマンド化/フック化
4. **段階的アプローチ** - 複雑なタスクは分割
5. **継続的改善** - CLAUDE.md とエージェントを育てる
