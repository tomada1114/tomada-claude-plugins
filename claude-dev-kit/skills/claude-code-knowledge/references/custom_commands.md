# 07. カスタムスラッシュコマンドの作成

## カスタムコマンドとは

頻繁に使用するプロンプトをコマンドとして保存できる機能です。毎回同じ指示を書く手間を省き、一貫性のある開発が可能になります。

### RPGで例えると：「/attack スライム」

RPGで主人公に「スライムを倒して」と言うと、毎回「位置を確認します...」「武器はどうしますか？」と聞かれるのは面倒です。そこで `/attack` コマンドを作ると：

```
/attack スライム
→ 主人公: (スライムの場所に向かう → 攻撃)
→ スライムを倒した！
```

**確認も説明もなく、すぐに実行してくれます。**

これがカスタムコマンドの本質です：
- **何をやるか**を定義する
- 毎回の確認や説明をスキップできる
- 引数を渡せる（例: `/attack スライム`）

> **Source**: https://zenn.dev/yahsan2/articles/claude-code-game-analogy (2025-12-17 確認)

## コマンドの種類

### プロジェクトコマンド
特定のプロジェクト専用のコマンド

- **場所**: `.claude/commands/`
- **スコープ**: 現在のプロジェクトのみ
- **使用法**: `/command-name`（説明に `(project)` と表示）
- **共有**: Git でチームと共有

### パーソナルコマンド（Personal Commands）
すべてのプロジェクトで使用できる個人用コマンド

- **場所**: `~/.claude/commands/`
- **スコープ**: すべてのプロジェクト
- **使用法**: `/command-name`（説明に `(user)` と表示）
- **共有**: 個人用（ユーザー固有）

**注意**: 同名のコマンドが存在する場合、プロジェクトコマンドが優先されます。

## コマンドの作成方法

### 基本構造

コマンドファイルは Markdown 形式で、フロントマター(YAML)を含みます:

```markdown
---
description: このコマンドの説明
---

# コマンド名

コマンドの詳細な説明と、Claude に実行してほしい指示
```

### YAML フロントマターのフィールド

| フィールド | 目的 | デフォルト |
|-----------|------|----------|
| `description` | コマンドの簡潔な説明 | プロンプトの1行目 |
| `allowed-tools` | コマンドが使用できるツール | 会話全体の設定を継承 |
| `argument-hint` | 引数のヒント表示（オートコンプリート時） | なし |
| `model` | 特定のモデル指定 | 会話全体の設定を継承 |
| `disable-model-invocation` | Claudeによる自動実行を禁止 | false |

### フロントマターフィールドの詳細

#### description：コマンドの説明を表示する

`description` は、コマンドの説明文を設定する項目です。設定した説明は、`/` を入力した際のサジェスト一覧に表示されます。

```yaml
---
description: Hello Worldを出力
---

ターミナルでHello Worldを出力してください。
```

**省略した場合**: プロンプト本文の最初の行が説明として使われます。複雑なコマンドでは明示的に設定することを推奨します。

#### allowed-tools：使用可能なツールを制限する

`allowed-tools` は、コマンド実行時に使用できるツールを制限する項目です。セキュリティや意図しない操作の防止に役立ちます。

**よく使うツールの指定パターン**:

| 指定 | 説明 |
|-----|------|
| `Bash(git:*)` | git 関連のコマンドすべて |
| `Bash(npm:*)` | npm 関連のコマンドすべて |
| `Read` | ファイルの読み取り |
| `Edit` | ファイルの編集 |
| `Write` | ファイルの作成・上書き |
| `Glob` | ファイルパターン検索 |
| `Grep` | テキスト検索 |

**注意点**: 制限が厳しすぎるとコマンドが正常に動作しないことがあります。最初は全てのツールを許可し、動作確認しながら必要なツールだけを制限していくのが効果的です。

#### argument-hint：引数のヒントを表示する

`argument-hint` は、コマンドの引数に関するヒントを設定する項目です。サジェストに引数の形式が表示されるので、使い方がわかりやすくなります。

```yaml
---
description: ファイルをリネーム
argument-hint: [old-path] [new-path]
---

古いパスを新しいパスにリネームしてください。
```

表示例:
```bash
> /rename  [old-path] [new-path]
  /rename     ファイルをリネーム (project)
```

### 例1: コミットメッセージ生成

**ファイル**: `.claude/commands/commit-msg.md`

```markdown
---
description: git の staged changes から適切なコミットメッセージを生成
---

# Commit Message Generator

以下の手順でコミットメッセージを生成してください:

1. `git diff --staged` を実行して変更内容を確認
2. 以下の形式でコミットメッセージを提案:
   - 1行目: 50文字以内の要約(現在形・命令形)
   - 2行目: 空行
   - 3行目以降: 詳細な説明

## コミットメッセージの原則
- 何を変更したか(What)と、なぜ変更したか(Why)を記載
- どのように変更したか(How)は不要
- 影響を受けるコンポーネントを明記
- 日本語で記載
```

使用方法:
```bash
/commit-msg
```

### 例2: セキュリティ監査

**ファイル**: `.claude/commands/security-audit.md`

```markdown
---
description: コードベースのセキュリティ脆弱性をチェック
---

# Security Audit

プロジェクト全体のセキュリティ脆弱性をチェックし、重要度順に報告してください。

## チェック項目
1. **認証・認可**
   - パスワードのハッシュ化
   - セッション管理
   - アクセス制御

2. **入力検証**
   - SQL インジェクション
   - XSS 攻撃
   - CSRF 対策

3. **データ保護**
   - 機密情報のハードコード
   - API キーの露出
   - 暗号化の実装

4. **依存関係**
   - 既知の脆弱性を持つパッケージ
   - 古いバージョンの使用

## 報告形式
各問題について:
- 重要度(高/中/低)
- 場所(ファイル名と行番号)
- 問題の説明
- 推奨される修正方法
```

使用方法:
```bash
/security-audit
```

### 例3: ドキュメント生成

**ファイル**: `~/.claude/commands/doc-gen.md`

```markdown
---
description: 関数やクラスのドキュメントを自動生成
---

# Documentation Generator

指定されたコードに対して、適切なドキュメントを生成してください。

## ドキュメント形式

### JavaScript/TypeScript
- JSDoc 形式
- 関数の説明
- @param でパラメータ説明
- @returns で戻り値説明
- @example で使用例

### Python
- Google Style Docstring
- 関数の目的
- Args: パラメータ説明
- Returns: 戻り値説明
- Raises: 例外説明
- Example: 使用例

### Java
- Javadoc 形式
- クラス/メソッドの説明
- @param でパラメータ
- @return で戻り値
- @throws で例外

## 注意点
- 既存のドキュメントがある場合は更新
- コードの実装詳細ではなく、使い方を説明
- 具体的な使用例を含める
```

使用方法:
```bash
/doc-gen
```

## 引数を使ったコマンド

### 引数の取得方法

コマンドに引数を渡す方法は2種類あります:

| 変数 | 説明 |
|------|------|
| `$ARGUMENTS` | すべての引数を取得（引数全体を1つの文字列として受け取る） |
| `$1`, `$2`, `$3`... | 位置指定で個別引数を取得 |

**注意**: 引数を渡さなかった場合、`$ARGUMENTS` は空文字列となり、意味のないプロンプトが生成されてしまう可能性があります。プロンプト側で補完対応を考慮するか、`argument-hint` を設定して引数が必要なことを明示することを推奨します。

### 引数入力のコツ

`/fix-issue` とタイプしてすぐに Enter を押すと、引数なしでコマンドが実行されてしまうため注意が必要です。引数を入力するには、以下の手順で操作しましょう:

1. `/fix-issue` とタイプ
2. **Tab キーでコマンドを選択**（または矢印キーで選択して Tab）
3. スペースを入力
4. 引数を入力（例: `123`）
5. Enter で実行

この流れを覚えておくと、引数付きのコマンドをスムーズに実行できるようになります。

### 例: $ARGUMENTS を使う

**ファイル**: `.claude/commands/fix-issue.md`

```markdown
---
description: GitHub Issue を修正
argument-hint: <issue-number>
---

# Fix Issue

Issue #$ARGUMENTS を修正してください。

## 手順
1. Issue の内容を理解
2. 関連するコードを特定
3. 修正を実装
4. テストを追加
5. コミットメッセージを準備
```

使用方法:
```bash
/fix-issue 123
# → Issue #123 を修正
```

### 例: エラーメッセージ分析

**ファイル**: `.claude/commands/search-error.md`

```markdown
---
description: エラーメッセージを検索して原因を調査
argument-hint: <error-message>
---

以下のエラーについて調査し、原因と修正方法を提案してください。

$ARGUMENTS
```

使用方法:
```bash
/search-error TypeError: Cannot read property 'map' of undefined
```

これで Claudeはエラーメッセージを分析し、プロジェクト内で原因と修正方法を提案してくれます。

### 例: 位置引数を使う

**ファイル**: `.claude/commands/compare.md`

```markdown
---
description: 2つのファイルを比較
argument-hint: <file1> <file2>
---

$1 と $2 を比較して違いを説明してください。
```

使用方法:
```bash
/compare src/old.js src/new.js
# → $1 = src/old.js, $2 = src/new.js
```

### 位置引数をファイル参照と組み合わせる

`@` 記法と位置引数を組み合わせて、動的なファイル参照が可能です：

**ファイル**: `.claude/commands/compare-files.md`

```markdown
---
description: 2つのファイルを比較
argument-hint: [ファイル1] [ファイル2]
---

@$1 と @$2 を比較し、差分を説明してください。
特に重要な違いがあれば強調してください。
```

`/compare-files src/old.ts src/new.ts` と実行すると、両ファイルの内容がコンテキストに読み込まれ、Claudeから詳細な差分の説明を得られます。

### 位置引数の注意点

#### 引数が足りない場合の挙動

**指定した位置に引数がない場合、その `$N` は空文字列に置き換わります。**

```markdown
# .claude/commands/greet.md

$1さん、$2の件についてお聞きします。
```

このコマンドを `/greet 田中` と実行すると（引数が1つだけ）、結果は以下のようになります：

```
田中さん、の件についてお聞きします。
```

`$2` が空文字列になるため、文として不自然な出力になります。そのため、プロンプト内でClaudeに判断を委ねるか、`argument-hint` で必要な引数を明示しておくとよいでしょう。

#### スペースを含む引数には制約がある

位置引数はスペースで区切られるため、**スペースを含む値を1つの引数として渡すことが難しい**点に注意が必要です。クォートで囲んでもそのまま引数の一部として扱われる可能性があります。スペースを含むファイル名を扱う場合は、別の方法を検討してください。

### 位置引数の実用例

#### ファイルのリネーム

```markdown
# .claude/commands/rename.md

$1 を $2 にリネームしてください。
```

#### ファイルの移動

```markdown
# .claude/commands/move.md

$1 を $2 ディレクトリに移動してください。
```

#### PRレビュー準備

```markdown
# .claude/commands/prepare-pr.md
---
description: PRレビュー用の情報を準備
argument-hint: [ブランチ名] [変更カテゴリ]
---

PR作成前の情報を準備してください。

- ブランチ: $1
- カテゴリ: $2 (feat/fix/refactor/docs)

以下を実行してください：
1. mainとの差分ファイル一覧を表示
2. 差分内容を分析
3. 簡潔なPR説明文を生成
```

## ディレクトリによるコマンド整理

サブディレクトリを使ってコマンドを整理できます:

```
.claude/commands/
├── git/
│   ├── commit-msg.md
│   └── squash.md
├── test/
│   ├── unit.md
│   └── e2e.md
└── deploy/
    ├── staging.md
    └── production.md
```

**重要**: サブディレクトリに配置したコマンドは、ディレクトリ名が `:` で区切られてコマンド名に含まれます:

```bash
/git:commit-msg    # git/commit-msg.md
/git:squash        # git/squash.md
/test:unit         # test/unit.md
/deploy:staging    # deploy/staging.md
```

`/` を入力するとサジェストに表示されるため、関連コマンドをまとめて管理できます:

```bash
> /test:
  /test:unit      ユニットテストを実行 (project)
  /test:e2e       E2Eテストを実行 (project)
```

`/help` で確認すると、ディレクトリ名は説明に `(project:git)` のように表示されます。

**ネームスペーシングの利点**:
- 関連するコマンドをグループ化できる
- `:` プレフィックスで関連コマンドを一括サジェスト
- パーソナルコマンドとプロジェクトコマンドで同名ファイルが存在しても共存可能（ネームスペース表示で区別）

## ファイル参照と Bash 実行

### ファイル参照（`@` プレフィックス）

コマンド内で他のファイルを参照できます:

```markdown
---
description: 実装をレビュー
---

@src/utils/helpers.js の実装をレビューしてください。
@src/old-version.js と @src/new-version.js を比較してください。
```

### Bash 実行（`!` プレフィックス）

コマンド内で Bash を直接実行できます:

```markdown
---
description: Git 状態を確認してコミット
allowed-tools: Bash(git add:*), Bash(git status:*), Bash(git commit:*)
---

現在の状態: !`git status`
差分: !`git diff HEAD`

上記を確認してコミットしてください。
```

**注意**: `allowed-tools` で明示的に Bash コマンドを許可する必要があります。

## ベストプラクティス

### 1. 明確な description を書く
description は `/help` で表示されるので、分かりやすく書きましょう。

❌ 悪い例:
```yaml
description: テスト
```

✅ 良い例:
```yaml
description: ユニットテストを実行し、カバレッジレポートを生成
```

### 2. 詳細な手順を記載
Claude に何をしてほしいか、具体的に書きます。

### 3. コマンドは小さく保つ
1つのコマンドで1つの責任。複雑なタスクは複数のコマンドに分割。

### 4. チーム規約を反映
プロジェクトコマンドはチームの規約やワークフローを反映させます。

### 5. 頻繁に使う操作を優先
自動化の効果が高い操作からコマンド化します。

## コマンドの反映タイミング

新しいコマンドを追加・編集した場合、すぐには反映されません。以下のいずれかの方法で反映させてください:

### セッション再起動
```bash
# Claude Code を終了
/exit

# 再度起動
claude
```

### 注意事項
- コマンドの**追加**も**編集**も、セッション再起動が必要
- コマンドが認識されない場合は、まずセッション再起動を試す

## コマンドの管理

### コマンド一覧を確認
```bash
/help
```

### コマンドを編集
ファイルを直接編集するか、Claude に依頼:

```bash
> .claude/commands/commit-msg.md を編集して、絵文字を追加して
```

### コマンドを削除
ファイルを削除:

```bash
rm .claude/commands/old-command.md
```

```markdown

# Test Coverage

2. カバレッジレポートを分析
```

```markdown
---
description: コードの重複を見つけて共通化

1. プロジェクト全体で重複コードを検索
2. 共通化できる部分を特定
3. ユーティリティ関数またはコンポーネントに抽出
```

### パフォーマンス最適化
```markdown
---
description: パフォーマンスボトルネックを特定して最適化

   - 実装の容易さ
   - 期待される改善度

```

## 高度な機能

### SlashCommand ツールによる自動実行

AI がプロンプト内で `/command` を参照すると、自動的に実行できます（`disable-model-invocation: false` の場合）:

```markdown
# CLAUDE.md やプロンプトに記載
テストを書く前に /write-unit-test を実行してください。
```

**SlashCommand ツールの権限設定**:

```bash
# 特定コマンドのみ許可
/permissions
# Allow: SlashCommand:/commit (引数なし)
# Allow: SlashCommand:/review-pr:* (任意の引数)

# すべての SlashCommand 実行を禁止
/permissions
# Deny: SlashCommand
```

### 文字予算制限

大量のコマンドがある場合、SlashCommand ツールは文字予算（デフォルト 15,000 文字）内のコマンドのみを Claude に表示します:

```bash
# カスタム設定
export SLASH_COMMAND_TOOL_CHAR_BUDGET=20000
```

### 拡張シンキングの統合

スラッシュコマンド内で拡張シンキングキーワードを含めることで、自動的にシンキングモードが発動します。

## スラッシュコマンド vs スキル

| 比較項目 | スラッシュコマンド | スキル |
|---------|------------------|-------|
| 用途 | シンプルな頻用プロンプト | 複雑なワークフロー |
| ファイル構成 | 単一 .md ファイル | 複数ファイル+ディレクトリ |
| 発見 | 明示的に呼び出し（`/command`） | 文脈から自動発見 |
| 例 | `/review` | 複数ステップのコード審査スキル |

**使い分けの指針**:
- よく使う短いプロンプト → スラッシュコマンド
- 複数のスクリプトやファイルが必要 → スキル
