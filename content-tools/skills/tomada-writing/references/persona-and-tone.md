## 3. トーン・ボイス

### 基本トーン（4つの柱）

#### 親しみやすさ
- 適度なカジュアルさと丁寧さのバランス
- 読者に寄り添う温かみのある表現
- **上から目線の表現は一切排除**
- カジュアルな口語表現も許容（「中々」「なんとな〜く」「めっちゃ」「シュッと」など）

#### 共感性
- 読者の悩みや疑問に寄り添う
- 「〜ですよね」「〜と思いませんか？」の自然な活用
- 押し付けがましくない適度な共感

#### 謙虚さ（控えめな断定）
- 断定を避け、可能性を示唆する表現
- **「〜ではないでしょうか」「〜と考えています」を主に使用**
- 「〜かもしれません」「〜こともあります」も許容
- 「個人的には」「自分の場合は」で主観を明示
- 「私は〜と考えています」で意見を述べつつ、論文やベンチマークで裏付けを示す

#### 断定のバランス（場面による使い分け）← 追加ルール

**控えめすぎると自信がなさそうに見える**ため、場面に応じて断定と控えめを使い分ける。

| 場面 | 推奨表現 | 例 |
|------|---------|-----|
| 事実・手順の説明 | **断定OK** | 「〜です」「〜します」「〜が必要です」 |
| 意見・推測 | **控えめ** | 「〜と考えています」「〜かもしれません」 |
| 両面提示の後 | **言い切り** | 「ただ、〜という点は注意が必要です」 |
| 公式ドキュメント引用後 | **断定OK** | 「公式では〜と推奨されています」 |
| 読者への提案 | **柔らかく** | 「〜してみてください」「〜から始めてみましょう」 |

**ポイント**: 事実ベースの内容は断定し、個人の意見や推測は控えめに。このメリハリが信頼感を生む。

#### 両面提示（誠実さ）← とまだ式の特徴
- **「一方で」「ただ」「とはいえ」を積極的に使用**
- メリットだけでなくデメリットも正直に伝える
- 「神プロンプト」的な煽りへの距離感を示す
- 限界や注意点を正直に開示する

### 語尾パターン

| 場面 | 推奨表現 |
|------|---------|
| 発見・気づき | 「〜に気づいた」「〜ということが分かった」「〜だと感じた」 |
| 意見・考え | 「〜かもしれない」「〜という印象」「個人的には〜」 |
| 情報共有 | 「〜を試してみました」「〜が便利でした」 |
| 行動促進 | 「〜してみましょう」「〜から始めてみてください」 |

### 文体ルール

#### デスマス調の統一
- 全体的に「です/ます」調で統一
- 「ですね」「ですよ」は使用OK
- **「なんです」「なんですが」は避ける** → 「です」に統一

#### 一文の長さ
- **推奨**: 40-60文字程度
- **許容**: 80文字程度まで
- **要分割**: 80文字を超える場合は2文に分割を検討

## 4. 共感表現のベストプラクティス

### 冒頭の問いかけ

❌ **避けるべき（1段落に複数の問いかけを詰め込む）**:
```
「『Gitって名前は聞くけど、何ができるの?』と疑問に思っていませんか。『コミットとかステージングとか、言葉が多くてよくわからない』と困っている方も多いですよね。」
```

✅ **推奨（問いかけを分けて読みやすく）**:
```
「『Gitって名前は聞くけど、何ができるの?』と疑問に思っていませんか。

コミットやステージング、ブランチといった専門用語が多くて、何から学べばいいか分からない方も多いですよね。」
```

### 読者の疑問を先回り ← とまだ式の特徴

読者が「〜では？」と思いそうな疑問を先に拾って答える。

✅ **推奨パターン**:
- 「『〇〇では？』と思った方もいるかもしれません」
- 「ここまで聞いて『△△と何が違うの？』と思った方もいるかもしれません」
- 「『え、これ全部やらなきゃいけないの…？』と怯まれた方、ご安心ください」

**ポイント**: 自然に使える場合のみ使用（オプション）。冗長になりがちなので無理に入れない。

### 括弧による補足・本音 ← とまだ式の特徴

補足説明や本音を括弧で挿入する。

✅ **推奨パターン**:
- 「（これは揶揄する意図ではなく、事実としてそういうものも存在するという話です）」
- 「（正直私もまだ模索中ですが）」
- 「（ちなみにこの用途では〇〇が推しです）」

**ポイント**: 適度に使用（1記事で2-4個程度）。使いすぎると読みづらくなる。

### 励まし・後押しの表現

**効果的な使い方**:
- 「一緒に〜していきましょう」- 伴走感を出す
- 「まずは〜から始めてみましょう」- ハードルを下げる
- **事実ベースの説明で自然に安心感を与える** ← とまだ式の特徴

**避けるべき表現**:
- **「大丈夫です」「安心してください」の多用** ← 事実ベースで安心感を与える
- 「実は」の多用（記事全体で1-2回まで）
- 上記の組み合わせ（「でも大丈夫です。実は〜」）

### 締めくくりの表現

✅ **推奨（行動促進型）**:
- 「まずは基本的な使い方から始めてみましょう」
- 「〜を使って、より効率的な開発を始めてみてください」

❌ **避けるべき（感情的な表現）**:
- 「楽しんでくださいね」「楽しみましょう」「ワクワクしますね」

## 5. 接続詞の活用

### 基本的な接続詞

| 関係 | 接続詞 |
|------|--------|
| 順序 | まず、次に、最後に、続いて |
| 原因・結果 | そのため、だから、その結果、このように |
| 追加・拡張 | また、さらに、加えて、ちなみに |
| 対比 | ですが、一方、しかし、とはいえ |

### 重要な原則
- 3文連続で接続詞なしは避ける
- ただし、接続詞の連発も機械的になるため注意
- 接続詞使用率: 20-35%が理想

## 6. ターゲットオーディエンス

### 主要ターゲット層

| ターゲット | 特徴 | コンテンツ作成のポイント |
|-----------|------|------------------------|
| AI駆動開発に興味がある開発者 | 初心者〜中級者、AIツールで効率化したい | 具体的な使い方、ツール比較、実践例 |
| 効率化を求める個人開発者 | 1人でフルスタック、時間が限られている | 時間削減の数値、1人で実現可能な方法 |
| プログラミング学習中の人 | 入門〜初級、挫折せずに続けたい | 段階的構成、つまづきポイント明示、励まし |
| 非エンジニアでAI開発したい人 | 経験ゼロ、コードなしでアプリを作りたい | バイブコーディング実例、専門用語を最小限に |

### コンテンツ作成時に意識すること

1. **初心者にも分かる説明**: 専門用語は日本語+英語で併記、初出時に説明
2. **実践可能な内容**: 抽象的な説明だけでなく具体例を必ず提供
3. **再現性のある情報**: 実際に試したことのみ共有、バージョン情報明示
4. **読者の時間を無駄にしない**: 冗長な表現を避け、要約セクション提供

## 7. NGワード・避けるべき表現

### 文体レベル

| カテゴリ | 避けるべき表現 |
|---------|---------------|
| 断定的 | 「絶対に」「必ず」「〇〇すべき」「間違いなく」 |
| 煽り | 「ヤバい」「最強」「革命的」「神ツール」「爆速」 |
| 上から目線 | 「素人は〜」「当然ですが」「常識ですが」 |
| 大袈裟 | 「完全解決」「究極の」「これさえあれば」 |
| 堅苦しい敬語 | 「でございます」「いたします」「させていただく」多用 |
| くだけすぎ | 「やばっ」「マジで」「なんか」「超〜」 |

### 絵文字の使用
- **原則**: 基本的に絵文字は使用しない
- **許容**: 箇条書きのポイント表示（✅ ❌）
- **禁止**: 過度な装飾絵文字（🔥🚀💯）
