**Version**: 2.2.0

## 冒頭パターン

### 記事型（Qiita/Zenn）- とまだ式

```markdown
こんにちは、とまだです。

【結論先出し】← とまだ式の重要ルール
例: 今回伝えたいことの要点は〇〇です。一言で言えば、△△ということになります。

【記事で得られる価値の明示 + 範囲の明示】
例: この記事では、〇〇から△△までを〇〇な視点から解説します。読み終わる頃には□□ができるようになります。

【共感的な問いかけ】← オプション（自然な場合のみ）
例: 「〇〇を始めたいけど、△△で不安...」と感じていませんか？

【公式ドキュメントへのリンク】（該当する場合）
例: https://example.com/docs/feature-name
```

**とまだ式の全体構造**: 導入 → 結論先出し → 詳細解説 → 余談 → 締め

1. 問題提起・読者の悩みに共感
2. 「今回伝えたいことの要点は〜」と結論を先に
3. 詳細をセクション分けで丁寧に解説
4. 「余談」で知的好奇心を満たす追加コンテンツ（任意）
5. 「以上」「それでは」で締め

## 公式ドキュメント引用パターン

技術記事において、公式ドキュメントやベストプラクティスを引用する場合のパターン。

### 引用ブロックの使い方

```markdown
Anthropic 公式が、ベストプラクティスとして触れている点も交えて紹介します。

>  Best practices for `.claude/rules/`:
>
> * **Keep rules focused**: Each file should cover one topic (e.g., `testing.md`, `api-design.md`)
> * **Use descriptive filenames**: The filename should indicate what the rules cover
> * **Use conditional rules sparingly**: Only add `paths` frontmatter when rules truly apply to specific file types
> * **Organize with subdirectories**: Group related rules (e.g., `frontend/`, `backend/`)
>
```

**引用のポイント**:
- 引用前に「公式が〜として触れている」など出典を明示
- **引用ブロックは英語原文のまま**（正確性を保つため）
- **引用後に日本語で解説を追加**（読者の理解を助ける）
- 引用ブロックの前後に空行を入れて視認性を確保

**引用+解説の例**:

```markdown
Anthropic 公式が、ベストプラクティスとして触れている点も交えて紹介します。

>  Best practices for `.claude/rules/`:
>
> * **Keep rules focused**: Each file should cover one topic
> * **Use conditional rules sparingly**: Only add `paths` frontmatter when rules truly apply to specific file types

### **1. 1ファイル1トピック**

`testing.md`、`api-design.md`など、1つのファイルには1つのトピックだけを書きましょう。

### **2. paths指定は控えめに**

全てのルールにpathsを指定する必要はありません。
```

### 公式リンクの配置

**配置ルール**: 公式ドキュメントへのリンクは**該当セクションの近く**に配置する。

```markdown
## .claude/rules/とは

`.claude/rules/`は、CLAUDE.mdを分割して管理するためのモジュラールール機能です。

Anthropic 公式も、ベストプラクティスの一つとして触れています。

https://code.claude.com/docs/en/memory#modular-rules-with-claude/rules/
```

**ポイント**:
- 導入部（冒頭）ではなく、該当機能を説明するセクションの近くに配置
- 「公式も〜として触れています」など、リンクの文脈を明示
- URLは単独行に配置し、Zennのカード表示を活かす

## 導入表現

### 概念を説明する時

✅ **推奨パターン**:
- 「簡単に言うと〜」
- 「〇〇とは、△△です」
- 「まず、〇〇について理解しましょう」

### 例えを使う時

✅ **推奨パターン**:
- 「例えば〜を想像してみてください」
- 「まるで〜のように」
- 「〜に似ています」

### 重要なポイントを示す時

✅ **推奨パターン**:
- 「実は〜です」
- 「ここで重要なのは〜」
- 「特に注意したいのは〜」

## 例えのメタファー集

### 本棚のメタファー（ファイル管理）

```
ファイルシステムは、本棚のようなものです。本（ファイル）を整理するために、棚（ディレクトリ）を使って分類します。
```

### 料理のメタファー（プログラミング）

```
プログラミングは料理に似ています。レシピ（コード）に従って、材料（データ）を調理（処理）することで、完成品（アプリ）が出来上がります。
```

### 自動販売機のメタファー（API）

```
APIは自動販売機のようなものです。お金を入れて（リクエスト）ボタンを押せば、飲み物が出てくる（レスポンス）。中の仕組みを知らなくても使えます。
```

### ゲームのセーブポイントメタファー（Git）

```
Gitは、ゲームのセーブポイントのようなものです。重要な変更の前にコミット（記録）しておけば、失敗しても安心です。
```

## とまだ式表現パターン

### 読者の疑問を先回りするパターン（オプション）

読者が「〜では？」と思いそうな疑問を先に拾って答える。**使用は任意**です。自然に使える場合のみ使用してください。

**パターン例**（使用は任意）:
- 「『〇〇では？』と思った方もいるかもしれません」
- 「ここまで聞いて『△△と何が違うの？』と思った方もいるかもしれません」
- 「『え、これ全部やらなきゃいけないの…？』と怯まれた方、ご安心ください」
- 「そう感じている方も多いのではないでしょうか」

**注意**: 無理に入れると文章が回りくどくなる場合があります。

### 括弧による補足・本音パターン

補足説明や本音を括弧で挿入する。1記事で2-4個程度。

✅ **推奨**:
- 「（これは揶揄する意図ではなく、事実としてそういうものも存在するという話です）」
- 「（正直私もまだ模索中ですが）」
- 「（ちなみにこの用途では〇〇が推しです）」
- 「（正直ノウハウを集めるだけなのはそんなに大変ではない）」

### 両面提示パターン

メリットだけでなくデメリットも正直に伝える。「一方で」「ただ」「とはいえ」を積極的に使用。

✅ **推奨**:
- 「〇〇は便利ですが、一方で△△には向かない場合もあります」
- 「ただ、〜という限界もあります」
- 「とはいえ、〜というリスクも存在します」
- 「こうした情報は一見すると魅力的に映りますし、実際に役立つこともあるでしょう。ただ、ふと気づくことがあります」

### 論文・公式ドキュメント引用パターン

信頼感を生むために、論文やベンチマーク結果を引用する。

✅ **推奨**:
```markdown
研究では、〇〇という現象が観察されています。詳しくは以前の動画で解説していますが、簡単に言うと△△という現象です。

[論文タイトル](URL)
```

**引用のポイント**:
- 引用前に「公式が〜として触れている」など出典を明示
- 引用後に日本語で解説を追加（読者の理解を助ける）
- 限界の明示: 「これだけでは〜できない」「正直〜は難しい」

## 励まし・後押しの表現

### ハードルを下げる表現

✅ **推奨**:
- 「大丈夫です」
- 「心配いりません」
- 「難しく見えますが、実は〜」
- 「まずは〜から始めてみましょう」

### 伴走感を出す表現

✅ **推奨**:
- 「一緒に〜していきましょう」
- 「順番に見ていきましょう」
- 「一つずつ確認していきましょう」

### 不安を和らげる表現

✅ **推奨**:
- 「失敗しても簡単に元に戻せるので、安心して試してみてください」
- 「エラーが出ても焦らなくて大丈夫です」
- 「よくあることなので、心配いりません」

## 締めくくりの表現

### 行動促進型

✅ **推奨**:
- 「まずは基本的な使い方から始めてみましょう」
- 「〜を使って、より効率的な開発を始めてみてください」
- 「次の手順で実際に試してみましょう」
- 「ぜひ試してみてください」

### 価値再確認型

✅ **推奨**:
- 「この方法を使えば、〜を効率化できます」
- 「参考になれば幸いです」
- 「お役に立てれば嬉しいです」

### 宣伝セクション（記事末尾）

記事の「まとめ」の後に、自然な流れで宣伝を追加する。

```markdown
## ちょっと宣伝：AI駆動開発を体系的に学びたい方へ

冒頭でも触れましたが Udemy では AI 駆動開発講座を複数開講しており、いくつかベストセラーもいただいています。

最大で 90%OFF のクーポンも配布しておりますので、これから学ぶ方はぜひご利用ください。

Webアプリやスマホアプリ、Pythonなど、多くの分野で講座を開講しています！

https://www.vibecodingstudio.dev/coupons?topic=claude-code


Xをフォローいただけると嬉しいです！AI駆動開発（特に Claude Code）のノウハウや Tips をよく発信しています！

https://x.com/muscle_coding
```

**宣伝セクションのポイント**:
- 見出しは「ちょっと宣伝」など控えめに
- URLはZennのカード表示を活かすため単独行に配置
- 冒頭の著者紹介と呼応させる

**トピック連動ルール**:
- Claude Code関連の記事: `?topic=claude-code` パラメータを付ける
- それ以外の記事: クエリパラメータなしの基本URL

```markdown
<!-- Claude Code関連記事 -->
https://www.vibecodingstudio.dev/coupons?topic=claude-code

<!-- その他の記事 -->
https://www.vibecodingstudio.dev/coupons
```

### X投稿の締めくくり

✅ **推奨**:
- 「〜かもしれません」
- 「〜という印象です」
- 「〜が便利でした」

❌ **避けるべき**:
- 「楽しんでくださいね」
- 「楽しみましょう」
- 「ワクワクしますね」

✅ **推奨**:

```
[状況や文脈]で気づいたけど、
[具体的な発見]

[理由や根拠]

[これからのアクション]かもしれない
```

```
[ツール名]の便利な使い方：

[具体的な方法]
→ [効果・メリット]

[補足や注意点]
```

## 記事構成のテンプレート

### 基本構成

```markdown
# タイトル

冒頭の挨拶と問いかけ

## 忙しい人のために要約
（3-5項目）

## 〇〇とは（概念）
## 準備・環境構築（準備）
## 基本的な使い方（基礎）
## 実践：〇〇を作ってみる（応用）
## よくあるエラーと対処法（補足）
## まとめ（総括）
```
