# とまだ式記事執筆ワークフロー

**Version**: 1.0.0
**Last Updated**: 2025-12-16

このドキュメントは、とまだ式記事執筆の完全ワークフローガイドです。

---

## ワークフロー全体像

### 通常モード（重め・中程度テンプレート）

```
1. ファイル読み込み & モード判断
2. テンプレート選択（5つから選択）
3. Plan mode（構成ヒアリング）
4. ExitPlanModeで承認取得
5. 初稿作成（元ファイルを直接編集）
6. 自動評価スクリプト実行
7. ルールベース評価（evaluation-rules.md参照）
8. 改善実施
9. 再評価（95点以上まで繰り返し）
10. 太字化（最終仕上げ）
11. 完了報告
```

### 軽めモード（TIL・感想型テンプレート）

```
1. ファイル読み込み & モード判断
2. テンプレート選択（TIL or 感想型）
3. 簡易構成確認（Plan modeスキップ可）
4. 初稿作成（テンプレートに沿って執筆）
5. 自動評価スクリプト実行
6. 改善実施（必要に応じて）
7. 再評価（80点以上で完了）
8. 完了報告
```

---

## ステップ0: ファイル読み込みとモード判断

### 1. ファイルを読み込む

ユーザーが指定したMarkdownファイルをReadツールで読み込みます。

### 2. モードを自動判断する

ファイルの内容を分析して、3つのモードのいずれかを判断:

| モード | 条件 | アプローチ |
|--------|------|-----------|
| タイトルのみ | frontmatterのみ、本文が空 | ゼロから記事を構築 |
| ざっくりメモ | 箇条書きメモ、見出しだけ | メモの意図を保ちながら肉付け |
| リライト | ある程度完成した本文がある | 元の主題を保ち、とまだ式要素を追加 |

### 3. テンプレートを選択する

AskUserQuestionツールで5つのテンプレートから選択:

| テンプレート | 重さ | 文字数 | 評価基準 | 用途 |
|------------|------|--------|---------|------|
| 体系的チュートリアル型 | 重め | 3000-5000字 | 95点 | 機能の体系的解説 |
| 検証レポート型 | 重め | 2000-4000字 | 95点 | 使い込んだ感想・検証 |
| 比較分析型 | 中程度 | 1500-3000字 | 95点 | A vs Bの比較 |
| 今日の発見（TIL）型 | 軽め | 500-1000字 | 80点 | 今日わかったこと |
| 使ってみた感想型 | 軽め | 300-800字 | 80点 | ファーストインプレッション |

→ **テンプレート詳細**: `templates/` ディレクトリ参照

## ステップ1: Plan Mode（計画立案）

> **Note**: 軽めモード（TIL・感想型）ではPlan modeをスキップ可能。直接執筆に進んでもOK。

### 目的

執筆を開始する前に:
1. タイトルをAI評価し、改善提案
2. 詳細な構成案を作成（H2/H3/H4見出し + 段落構成案）
3. ユーザーと対話的にヒアリング
4. ExitPlanModeで計画を提示し、承認を得る

### タイトル評価（70点未満の場合）

複数の改善案を提示:

```markdown
【現在のタイトル】
「Gitの使い方」
評価: 55点（ターゲット不明、具体性不足）

【改善案1】パターン2（ターゲット明示）+ パターン5（数値）
「【初心者向け】Git入門 - 5つの基本コマンドでバージョン管理を始める」
評価予測: 82点

【改善案2】パターン3（実用性）+ パターン1（対応環境）
「GitでチームCollaboration - コミット・ブランチ・マージを実践的に学ぶ」
評価予測: 78点
```

### 構成案の作成（レベル3）

以下を含む詳細な構成案を作成:

1. **H2/H3/H4見出し構造**
2. **各セクションの主要ポイント**（2-4個の箇条書き）
3. **段落構成案**（各段落の主張）
4. **日常的な例えの候補**
5. **コード例の配置案**

### ヒアリング項目（AskUserQuestion活用）

**原則**: 曖昧な点があれば、推測せずに質問する。何回か繰り返し質問してもOK。

#### 必須ヒアリング（最初に確認）

1. **テンプレート選択**
   - 5つのテンプレートからどれを使うか
   - 重さの希望（重め/中程度/軽め）

2. **ターゲット読者**
   - 初心者（Claude Code未経験）
   - 中級者（基本は知っている）
   - 現役エンジニア（実務で使いたい）

#### 構成ヒアリング（構成案提示後）

3. **見出し構成への同意**
   - このままでOK
   - 〇〇を追加したい
   - △△を削除したい
   - 順番を変えたい

4. **内容の詳細**
   - 含めたい具体例
   - 避けたいトピック
   - 強調したいポイント
   - コード例の有無・詳しさ

#### 方針ヒアリング（必要に応じて）

5. **トーン・スタイル**
   - カジュアル/フォーマル
   - 両面提示の程度（限界・デメリットをどこまで書くか）
   - 括弧補足の頻度

6. **長さ・詳しさ**
   - 文字数の目安
   - どこまで詳しく書くか
   - 省略してよい部分

#### ヒアリングの進め方

```
【ステップ1】テンプレート・ターゲット確認
↓
【ステップ2】構成案を提示
↓
【ステップ3】構成への同意・修正希望を確認
↓
【ステップ4】内容の詳細を確認（必要に応じて）
↓
【ステップ5】ExitPlanModeで最終承認
```

**注意**: 軽めモード（TIL・感想型）でも、テンプレート選択とターゲット確認は実施する。

### ExitPlanModeで承認取得

調整完了後、最終構成を提示してユーザーの承認を得る。

**承認前に確認すべきこと**:
- テンプレートが確定しているか
- ターゲット読者が明確か
- 見出し構成に同意が得られているか
- 含めたい/避けたい内容が明確か

## ステップ2: 初稿作成

### 完全直接編集方式

- ドラフトディレクトリの一時ファイルを使用しない
- ユーザーが指定した記事ファイルを**最初から直接編集**
- Git履歴で変更を管理

### モード別執筆ガイド

#### タイトルのみモード

1. とまだ式の冒頭パターンから執筆開始
2. Plan modeで決定した見出し構造に従って執筆
3. 各セクションを丁寧に執筆

#### ざっくりメモモード

1. メモから執筆者の意図を読み取る
2. メモの内容を活かしながら、とまだ式の構成に整える
3. 不足している情報を補完
4. **メモの主旨は変えない**（最重要）

#### リライトモード

1. 既存記事の主題、構成、技術的内容を分析
2. 残すべき内容と改善すべき点を特定
3. とまだ式の要素を追加・調整
4. **元の記事の主題や技術的内容は変えない**（最重要）

### とまだ式の必須要素

```markdown
こんにちは、とまだです。

【読者への共感的な問いかけ】

【記事で得られる価値の明示】

## 忙しい人のために要約

- 要点1
- 要点2
- 要点3
```

### 重要な原則

1. 段落と段落の間には改行を2つ
2. メイン見出し(##)は4-7個
3. 見出しの直後には必ず説明文を配置（見出し→箇条書きは避ける）
4. 見出しに入る前の前置き説明を避ける
5. 接続詞で文を自然に繋ぐ
6. 日常的な例えを適度に使用

## ステップ3: 自動評価

### 評価コマンド

```bash
python3 .claude/skills/tomada-writing/scripts/calculate_score.py <記事ファイル>
```

### 評価内容

| 項目 | 配点 | 内容 |
|------|------|------|
| 接続詞スコア | 40点 | 接続詞使用率、3文連続での接続詞不足 |
| NGワードスコア | 30点 | 避けるべき表現の使用状況 |
| 文体品質スコア | 30点 | 見出しなど構造的な品質 |

### 評価基準

- **A+（90点以上）**: 優秀 - 公開可能な高品質
- **A（70-89点）**: 良好 - 軽微な修正で公開可能
- **B（50-69点）**: 要改善 - 修正が必要
- **C（49点以下）**: 不合格 - 大幅な修正が必要

---

## ステップ4: ルールベース評価

自動評価に加えて、`evaluation-rules.md`に従い以下を評価:

### 評価項目

1. **文体・トーン評価**
   - 親しみやすさ
   - 共感表現
   - 励まし・後押し

2. **構造・見出し評価**
   - 冒頭構成
   - 見出し構造
   - 箇条書きの使い方
   - 感情曲線の設計

3. **抑揚・リズム評価**
   - 文末表現の黄金比
   - 接続詞の使用率
   - 問いかけと答えの構造

4. **表現・言い回し評価**
   - 日常的な例え
   - 導入フレーズ
   - 敬語レベル
   - 具体性と抽象性のバランス
   - 読者への配慮表現

### 統合評価レポート

自動スコアとルール評価を統合し、改善優先順位付きリストを作成。

---

## ステップ5: 改善実施

### 修正の優先順位

#### 1. 最優先（Critical）

- 「～しました」の繰り返し削除
- タイトルの過剰表現削除

#### 2. 高優先度（High）

- 接続詞不足の解消
- NGワードの置き換え
- 見出し前の前置き説明を削除
- 冒頭パターンの追加
- 要約セクションの追加

#### 3. 中優先度（Medium）

- 箇条書き導入の強化
- H4見出しの適切な使用
- 見出し直後の説明文追加
- 段落間の改行
- 文の長さ調整

#### 4. 低優先度（Low）

- 細かい表現の調整
- 「なんです」→「のです」など軽い表現の修正

---

## ステップ6: 再評価ループ

### ループの条件

**通常モード（重め・中程度テンプレート）**:
- **スコアが95点以上になるまで**、ステップ3-5を繰り返す（最大5回）
- 各イテレーションのスコアを記録し、向上を確認

**軽めモード（TIL・感想型テンプレート）**:
- **スコアが80点以上になるまで**、ステップ3-5を繰り返す（最大3回）
- 完璧を目指さない、継続性重視
- 80点に達しなくても、致命的な問題がなければ完了としてよい

### ループのフロー

```
自動評価 → ルール評価 → 改善実施 → 自動評価（繰り返し）
```

## ステップ7: 太字化（最終仕上げ）

**通常モード**: スコアが95点以上を達成した後、最終仕上げとして重要ポイントを太字化。

**軽めモード**: 80点以上で完了。太字化は省略可（短い記事では太字が少なくてもOK）。

### 太字化の対象

**太字にすべきもの**:
- 記事の核心となる主張や結論
- 読者が理解・記憶すべきキーコンセプト
- 行動のポイント
- 対比や強調

**太字にしてはいけないもの**:
- 技術用語の羅列
- 接続詞や助詞のみ
- 文全体
- 行全体
- コロンで終わる文

### 太字化の基準

- **割合**: 5-15%（目標: 10%）
- **分布**: 各セクションに均等に配置
- **段落ごと**: 2-3箇所以内

## ステップ8: 完了報告

### 通常モード: 95点以上達成時

```markdown
とまだ式記事の執筆が完了しました！

## 最終結果
- **総合スコア**: 96.5点（A+）
- **テンプレート**: 体系的チュートリアル型
- **イテレーション回数**: 3回

## スコア内訳
- 接続詞: 38/40点
- NGワード: 28/30点
- 文体品質: 28/30点

## 主な改善点
- 冒頭パターンの追加
- 接続詞不足の解消（15箇所）
- 太字化（重要ポイント12箇所を強調）

## 保存先
- ファイル: articles/git-beginner.md
```

### 軽めモード: 80点以上達成時

```markdown
軽め記事の執筆が完了しました！

## 最終結果
- **総合スコア**: 84点（A）
- **テンプレート**: 今日の発見（TIL）型
- **文字数**: 約650字

## 保存先
- ファイル: articles/til-claude-code-tips.md

---
検証レポートにまとめる価値があれば、後日深掘り記事に発展させることも検討してください。
```

### 95点未満で5回到達時

```markdown
イテレーション5回を完了しましたが、95点に到達しませんでした。

## 最終結果
- **最高スコア**: 88.5点（A）
- **到達イテレーション**: 5回

## 残りの問題点
1. 接続詞不足（残り5箇所）
2. 長い段落（残り2箇所）

## 95点到達のための改善提案
1. 接続詞不足箇所に「しかし」「その結果」を追加
2. 長い段落を2つに分割

手動で上記の修正を行うことで、95点以上に到達できます。
```

## フロントマター最適化

### タイトルの作り方

- **長さ**: 20-30文字（最大35文字）
- **避けるべき**: 「！」、「マスター」「完全攻略」

### emojiの選び方

| emoji | 用途 |
|-------|------|
| 📚 | 学習コンテンツ、入門記事 |
| 🔰 | 初心者向けガイド |
| 💡 | アイデア記事、問題解決 |
| 🛠️ | ツール紹介、設定方法 |
| 🎯 | 実践的な内容 |

### topicsの選び方

- **5個フル活用**: 必ず5個のトピックを指定
- **具体性重視**: 抽象的なタグより具体的なタグを優先
