# トラブルシューティングガイド

このドキュメントは、tomada-writingスキルでの**よくある問題と解決方法**をまとめたガイドです。

---

## スコアが上がらない場合

### 問題1: NGワードスコアが低い

**症状**: NGワードスコアが50点以下

**原因**:
- 避けるべき表現を多用している
- くだけすぎ・堅すぎる表現が混在している
- 過剰な表現（「劇的に」「革命的」など）を使っている

**解決方法**:

1. **NGワードリストを確認**

詳細は `script-usage.md` の「NGワード詳細」セクションを参照してください。

2. **同義の適切な表現に置き換える**

| NGワード | 適切な表現 |
|---------|----------|
| 劇的に | 大幅に、大きく |
| 革命的 | 画期的、効果的 |
| 開発ライフ | 開発作業、開発プロセス |
| めちゃくちゃ | 非常に、とても |
| ～じゃない | ～ではない |

3. **くだけすぎ・堅すぎる表現を修正**

**くだけすぎ**:
- 「なんです」→「のです」
- 「〜っぽい」→「〜のような」
- 「ヤバい」→「素晴らしい」「重要」

**堅すぎ**:
- 「〜である」→「〜です」
- 「〜だ」→「〜です」
- 「〜する」→「〜します」

4. **writing-style-checkerで確認**

```
writing-style-checker を使って <記事ファイルのパス> を評価してください
```

### 問題2: 構造スコアが低い

**症状**: 構造スコアが60点以下

**原因**:
- 見出しの数が不適切（少なすぎる or 多すぎる）
- 冒頭パターンがない
- 要約セクションがない
- H4見出しの使い方が不適切

**解決方法**:

1. **見出しを追加または統合**

- **H2見出しの推奨数**: 4-7個
- **H3見出しの推奨配置**: 各H2の下に2-4個

3. **冒頭パターンを確認**

```markdown
こんにちは、とまだです。

【読者への共感的な問いかけ】

【記事で得られる価値の明示】

## 忙しい人のために要約

- 要点1
- 要点2
- 要点3
- 要点4
```

4. **H4見出しの適切な使用**

H4見出しを作る判断基準:
- H3見出しの内容に2つ以上の独立したトピックがある
- 各H4見出しの下に十分な文章量（3段落以上、150文字以上）がある
- 1-2行だけのH4見出しは避ける

5. **structure-analyzerで確認**

```
structure-analyzer を使って <記事ファイルのパス> を評価してください
```

### 問題3: 接続詞スコアが低い

**症状**: 接続詞スコアが25点以下

**原因**:
- 3文連続で接続詞がない箇所が多い
- 接続詞の使用率が低い（5%未満）

**解決方法**:

1. **3文連続で接続詞がない箇所を特定**

自動スクリプトの出力から、該当箇所を確認：

```json
"three_consecutive_no_conjunction": [
  {"line": 120, "sentences": ["文1", "文2", "文3"]},
  {"line": 150, "sentences": ["文1", "文2", "文3"]}
]
```

2. **適切な接続詞を追加**

| 文脈 | 適切な接続詞 |
|------|-------------|
| 逆接 | しかし、ただし、ですが、一方で |
| 順接 | そのため、その結果、だから、したがって |
| 並列 | また、さらに、そして、加えて |
| 例示 | 例えば、具体的には、実際に |
| 説明 | つまり、すなわち、言い換えると |

**変更前**（接続詞なし）:
```markdown
Gitは便利です。コマンドが難しいです。基本だけ覚えれば大丈夫です。
```

**変更後**（接続詞あり）:
```markdown
Gitは便利です。しかし、コマンドが難しいと感じるかもしれません。ただし、基本だけ覚えれば大丈夫です。
```

3. **conjunction-checkerで確認**

```
conjunction-checker を使って <記事ファイルのパス> を評価してください
```

### 問題4: 特定の評価項目が低い

**症状**: サブエージェントの特定項目が15点以下

**原因**: 該当するリファレンスの基準を満たしていない

**解決方法**:

1. **該当するリファレンスドキュメントを熟読**

| 評価項目 | リファレンス |
|---------|-------------|
| 文体・トーン | `references/writing-style.md` |
| 構造・見出し | `references/structure.md` |
| 表現・言い回し | `references/expression.md` |
| 抑揚とリズム | `references/intonation.md` |
| コード例 | `references/code-examples.md` |
| 視覚要素 | `references/visual-elements.md` |
| 太字強調 | `references/bold-emphasis.md` |

2. **具体的な改善例を参考に修正**

各リファレンスには、具体的な改善例が記載されています。

3. **優（18-20点）の基準を目指す**

各リファレンスの「優（18-20点）」の基準を確認し、その水準を目指します。

### 問題5: 5回のイテレーションで95点に達しない

**症状**: イテレーション5回を使い切ったが、スコアが95点未満

**原因**:
- 改善の優先順位が適切でなかった
- サブエージェントの指摘を十分に反映していなかった
- 構造的な問題が残っている

**解決方法**:

1. **現状の最高スコアの版を最終稿とする**

2. **主な問題点をユーザーに報告**

以下の情報を含める：
- 最高スコアとグレード
- 残りの具体的な問題点（箇所とLine番号）
- 95点到達のための具体的な改善提案

**報告例**:
```markdown
## 残りの問題点

1. **接続詞不足**（残り5箇所）:
   - Line 120-125: 3文連続で接続詞なし
   - Line 200-205: 同上

2. **長い段落**（残り2箇所）:
   - Line 150-165: 12行の段落を分割推奨

3. **見出し直後の説明文不足**（残り1箇所）:
   - Line 180: H3見出し直後に箇条書き
```

3. **手動での微調整を提案**

ユーザーに、残りの問題点を手動で修正することを提案します。

## スクリプト実行エラー

### エラー1: ファイルが見つからない

**症状**:
```
FileNotFoundError: [Errno 2] No such file or directory: 'articles/git-beginner.md'
```

**原因**: ファイルパスが間違っている

**解決方法**:

1. **ファイルパスを確認**

相対パスではなく、プロジェクトルートからの相対パスを使用：

❌ 間違い:
```bash
python3 .claude/skills/tomada-writing/scripts/calculate_score.py git-beginner.md
```

✅ 正しい:
```bash
python3 .claude/skills/tomada-writing/scripts/calculate_score.py articles/git-beginner.md
```

2. **ファイルの存在を確認**

```bash
ls articles/git-beginner.md
```

---

### エラー2: Pythonスクリプトが実行できない

**症状**:
```
python3: command not found
```

**原因**: Python 3がインストールされていない

**解決方法**:

1. **Pythonのバージョンを確認**

```bash
python --version
python3 --version
```

2. **Pythonをインストール**

macOSの場合:
```bash
brew install python3
```

---

### エラー3: スクリプトの出力が文字化けする

**症状**: 日本語が正しく表示されない

**原因**: 文字エンコーディングの問題

**解決方法**:

1. **環境変数を設定**

```bash
export LANG=ja_JP.UTF-8
export LC_ALL=ja_JP.UTF-8
```

2. **スクリプトを再実行**

## サブエージェント実行エラー

### エラー1: サブエージェントが見つからない

**症状**: サブエージェントを実行しても反応がない

**原因**: サブエージェント定義ファイルが見つからない、または破損している

**解決方法**:

1. **定義ファイルを確認**

```bash
ls .claude/subagents/
```

以下のファイルが存在するか確認：
- `writing-style-checker.md`
- `structure-analyzer.md`
- `conjunction-checker.md`
- `expression-quality-checker.md`
- `bold-emphasis-checker.md`

2. **YAMLフロントマターを確認**

各ファイルの先頭に以下のようなフロントマターがあるか確認：

```yaml
---
name: writing-style-checker
description: ...
tools: ...
model: sonnet
---
```

3. **ファイルを修復**

問題がある場合は、元のファイルから復元します。

---

### エラー2: 並列実行が完了しない

**症状**: サブエージェントの並列実行が途中で止まる

**原因**: モデルのタイムアウト、またはコンテキスト超過

**解決方法**:

1. **記事のサイズを確認**

記事が非常に長い場合（15,000文字超）、分割して評価します。

2. **並列実行の数を減らす**

5つすべてではなく、2-3つずつ実行します：

```
writing-style-checker, structure-analyzer を使って <記事ファイルのパス> を並列評価してください
```

```
conjunction-checker, expression-quality-checker を使って <記事ファイルのパス> を並列評価してください
```

3. **順序実行に切り替える**

最後の手段として、順序実行に切り替えます：

```
writing-style-checker を使って <記事ファイルのパス> を評価してください
```

（結果を確認後、次のサブエージェントを実行）

## その他のトラブル

### トラブル1: Git管理されていないファイルを編集してしまった

**症状**: 完全直接編集方式で元ファイルを編集したが、Gitで管理されていなかった

**原因**: ファイルがGit管理外だった

**解決方法**:

1. **元に戻したい場合**

手動で元の内容をコピー＆ペーストで復元します。

2. **今後の予防策**

編筆開始前に、ファイルがGit管理されているか確認：

```bash
git status
```

### トラブル2: イテレーション中にスコアが下がった

**症状**: 改善したはずが、スコアが前回より下がった

**原因**: 改善により別の問題が発生した可能性

**解決方法**:

1. **スコアの内訳を確認**

どの項目が下がったか確認：

```json
{
  "breakdown": {
    "conjunctions": {"score": 35, "weighted_score": 14.0},
    "ng_words": {"score": 70, "weighted_score": 21.0},  // 前回: 85点
    "structure": {"score": 75, "weighted_score": 36.0}
  }
}
```

2. **サブエージェントで詳細確認**

該当する項目のサブエージェントを実行して、問題箇所を特定します。

3. **前回のバージョンと比較**

Git diffで前回のバージョンと比較し、何が変わったか確認：

```bash
git diff articles/git-beginner.md
```

4. **問題箇所を修正**
