# とまだ式禁止表現・NGワード集

**Version**: 2.0.0
**Last Updated**: 2025-12-16

このドキュメントは、すべての「とまだ式」コンテンツで**絶対に避けるべき表現**と**推奨される代替表現**をまとめたガイドです。

> **Note**: v2.0.0 より、`tone-and-style.md` の文体スタイル要素を統合。「大丈夫です」「安心してください」を事実ベースの表現に置き換えることを強化。

---

## 絶対に避けるべき行動

### 1. 著者の経験を捏造しない

❌ **悪い例**:
```markdown
私がプログラミングスクールで講師をしていたとき、多くの生徒がGitで挫折するのを見てきました。
```

✅ **理由**:
- とまだの過去の経験を勝手に作らない
- 具体的な経験談（講師時代の話など）は避ける
- 架空の経験談は信頼性を損なう

✅ **代替表現**:
```markdown
Gitを初めて使う人の多くは、コマンドの難しさで不安を感じることがあります。
```
→ 一般論として語るか、「〜という声をよく聞きます」などの客観的な表現を使う

---

### 2. 過度な例え話に依存しない

❌ **悪い例**:
```markdown
## Gitとは

Gitはまるでゲームのセーブポイントのようなものです。ゲームでボスと戦う前にセーブしておくのと同じように、Gitでは重要な変更の前にコミットしておくことができます。

セーブポイントがあれば、ボスに負けても安心ですよね。同じように、Gitがあれば、コードが壊れても過去の状態に戻ることができます。

ゲームの世界では...（以下、見出し1つ分が例え話だけで埋まる）
```

✅ **理由**:
- 例えはあくまで補助
- 1見出し分を例えだけで埋めない
- タイトルに例えを入れない（「〇〇を△△に例えて解説」は避ける）

✅ **代替表現**:
```markdown
## Gitとは

Gitは、変更履歴を記録してくれる便利なツールです。まるでゲームのセーブポイントのように、いつでも過去の状態に戻ることができます。

Gitを使うことで、以下のようなメリットがあります：
- 変更履歴を追跡できる
- 複数人での開発がしやすくなる
- 過去のバージョンに戻せる

それでは、Gitの基本的な使い方を見ていきましょう。
```
→ 例えは導入で軽く使い、すぐに本題に入る

### 3. 実践的すぎる内容に偏らない

❌ **悪い例**（エラー対処だけの記事）:
```markdown
## タイトル: Gitでよく遭遇する10のエラーと対処法

## エラー1: fatal: not a git repository
対処法: git initを実行してください

## エラー2: error: Your local changes to the following files would be overwritten by merge
対処法: git stashを実行してください

（以下、エラーの羅列のみ）
```

✅ **理由**:
- エラー対処だけの記事は避ける
- トラブルシューティングのみの構成は避ける
- 基礎的な概念や使い方を含めるべき

✅ **代替アプローチ**:
```markdown
## タイトル: 【初心者向け】Git入門 - 基本コマンドとよくあるエラー対処法

## Gitとは（基本概念）
## 基本的な3つのコマンド（基本的な使い方）
## 実践：はじめてのGitプロジェクト（実際の使用例）
## よくあるエラーと対処法（エラー対処は一部として含める）
```
→ 基礎から段階的に説明し、エラー対処は一部として含める

### 4. 過去記事とタイトルを被らせない

❌ **避けるべきタイトルパターン**:
- 「Gitで挫折しない方法」
- 「3ヶ月でマスターするGit」
- 「1ヶ月でGitを完全理解」
- 「Git完全攻略ガイド」

✅ **理由**:
- 「挫折」「3ヶ月で」「1ヶ月」「マスター」「完全理解」「完全攻略」は頻出ワード
- 大袈裟な表現は避ける
- タイトルは具体的で実用的な内容を示すべき

✅ **推奨タイトルパターン**:
- 「【初心者向け】Git入門 - 5つの基本コマンドでバージョン管理を始める」
- 「Gitの基本を実践的に学ぶ - コミット・ブランチ・マージの使い方」
- 「Git × GitHub入門 - 初めてのバージョン管理とリモートリポジトリ」

### 5. 見出しの直前に予告文を書かない

**重要原則：すべての見出し（H2/H3/H4）の直前に、次の内容を予告する文を置くことは絶対に避けてください。**

❌ **悪い例1**（「次は〜」パターン）:
```markdown
Gitの基本的な使い方を理解したところで、次は実際のコマンドについて見ていきましょう。

## 基本的な3つのコマンド
```

❌ **悪い例2**（「ここからは〜」パターン）:
```markdown
ここからは、Gitのインストール方法について説明します。

## Gitのインストール
```

❌ **悪い例3**（質問形式で次を予告するパターン）:
```markdown
大規模プロジェクトの例を紹介しましたが、小規模でも効果はあるのでしょうか?

## 小規模プロジェクトでの使い方
```

✅ **理由**:
- 見出しの直前に予告文を置くと、読者のリズムが分断される
- 見出しそのものが次のトピックを明示しているため不要
- 見出しの直後に説明文を配置すべきルールに反する
- 「次は〜」「ここからは〜」「〜でしょうか?」といった表現は冗長で不自然

✅ **正しいアプローチ**:
```markdown
## Gitとは

Gitは、変更履歴を記録してくれる便利なツールです。（中略）

これでGitの基本概念が理解できました。

## 基本的な3つのコマンド

Gitでは、変更を記録するために3つの基本コマンドを使います。
```
→ どのアプローチでも、**見出しの直前には何も書かず、見出しの直後に必ず説明文を配置**

### 6. 教科書特有の避けるべきこと（Zenn Book）

❌ **学習の目標を曖昧にしない**:
```markdown
## 学習の目標
- Gitについて学ぶ
- コマンドを理解する
```

✅ **代替表現**（具体的で測定可能な目標）:
```markdown
## 学習の目標
- Gitの基本概念（リポジトリ、コミット、ブランチ）を説明できる
- git add、git commit、git pushの3つのコマンドを使える
- ローカルとリモートの違いを理解し、GitHub連携ができる
```

❌ **まとめで新しい情報を追加しない**:
```markdown
## まとめ

この章では〜を学びました。

なお、さらに高度な機能として、git rebaseやgit cherry-pickもあります。次章で詳しく...
```

✅ **代替表現**（振り返りに徹する）:
```markdown
## まとめ

この章では、Gitの基本的な3つのコマンド（git add、git commit、git push）を学びました。これらを使えば、基本的なバージョン管理ができます。

次章では、ブランチを使った並行開発について学習します。
```

## 避けるべき表現パターン

### 文体レベルのNG表現

#### 断定的表現
❌ **避ける**:
- 「絶対に」「必ず」「〇〇すべき」
- 「間違いなく」「100%」
- 「〜しかない」「〜以外ありえない」

✅ **代替**:
- 「〜することをおすすめします」
- 「〜すると良いでしょう」
- 「〜が効果的です」

#### 煽り表現
❌ **避ける**:
- 「ヤバい」「最強」「革命的」
- 「神ツール」「爆速」
- 「圧倒的」「衝撃的」

✅ **代替**:
- 「便利な」「効率的な」
- 「非常に役立つ」
- 「大幅に改善する」

#### 上から目線
❌ **避ける**:
- 「素人は〜」「理解していない人は〜」
- 「当然ですが」「常識ですが」
- 「知らないのですか？」

✅ **代替**:
- 「初めて使う方は〜」
- 「まだ馴染みのない方も〜」
- 「〜をご存知でしょうか？」

#### 読者呼称「あなた」の使用禁止
❌ **避ける**:
- 「あなたは〜」「あなたの〜」「あなたが〜」
- 「あなたにとって」「あなたも〜」

✅ **代替**（文脈に応じて選択）:
- **「皆さん」**: 一般的な読者への呼びかけ（最も汎用的）
- **「開発者」**: 技術的な文脈、実装者を指す場合
- **「ユーザー」**: ツールやサービスの利用者を指す場合

**理由**:
- 「あなた」は個人を特定するニュアンスがあり、押し付けがましい印象を与える
- 技術記事では「皆さん」「開発者」「ユーザー」の方が自然で親しみやすい
- とまだのトーン（「先輩・同僚」スタイル）とも一致する

**使用例**:
```markdown
❌ 「あなたのプロジェクトで使えます」
✅ 「皆さんのプロジェクトで使えます」

❌ 「あなたが実装する際には」
✅ 「開発者が実装する際には」

❌ 「あなたがツールを使うとき」
✅ 「ユーザーがツールを使うとき」
```

#### 大袈裟な表現
❌ **避ける**:
- 「完全解決」「究極の」
- 「これさえあれば」「一生使える」
- 「全てが変わる」
- 「思ったより簡単」「意外と簡単」「驚くほど簡単」
- 「簡単に言うと」の多用（上から目線に聞こえる）
- **時間の断言**: 「〇分で完了」「数分で終わる」「すぐに完了」「あっという間」

✅ **代替**:
- 「効果的に解決できる」
- 「非常に便利な」
- 「開発効率が向上する」
- 「シンプルな手順です」「分かりやすい構造です」
- 「要約すると」「つまり」（「簡単に言うと」の代わり）
- 時間に言及せず、手順の明確さを示す

#### 堅苦しい敬語
❌ **避ける**:
- 「でございます」「いたします」
- 「〜させていただく」の多用
- 「〜申し上げます」

✅ **代替**:
- 「です」「ます」
- 「〜します」
- 「〜お伝えします」

#### くだけすぎた表現
❌ **避ける**:
- 「やばっ」「マジで」
- 「なんか」「超〜」
- 「〜じゃん」「〜って感じ」

✅ **代替**:
- 「驚きました」「とても」
- 「〜のような」「〜という印象」
- 「〜です」「〜のようです」

#### コロンで終わる文（2025-11-15追加）
❌ **避ける**:
- 「改めて要点をまとめます：」
- 「主なポイントは以下の通りです：」
- 「具体的には次のようになります：」
- 文末がコロン（:）や全角コロン（：）で終わる表現全般

✅ **代替**:
- 「改めて要点をまとめます。」（句点で終わる）
- 「主なポイントは以下の通りです。」
- 「具体的には次のようになります。」
- または、箇条書きの導入文として自然に繋ぐ

**理由**:
- 日本語の文章では文末にコロンを使うのは不自然
- 箇条書きの導入文は句点で終わるべき
- コロンは英語圏の文法であり、日本語では違和感がある

❌ **避けるべき冗長表現**:
```markdown
まず最初に、初めてGitを使う人は、最初のステップとして、まずはインストールから始める必要があります。
```

✅ **改善**:

```markdown
Gitを初めて使う場合、まずはインストールから始めましょう。
```


### 過度な安心表現（文体ルール更新 2025-12-16）

❌ **避けるべき（過度な安心・励まし表現）**:
- **「大丈夫です」「安心してください」** ← とまだ式では使用を控える
- 「実は」の多用（驚きを演出する大げさな表現）
- 上記を組み合わせた表現（「でも大丈夫です。実は〜」など）

✅ **推奨（事実ベースで安心感を与える）** ← とまだ式の特徴:
- 「〜には理由があります」「〜という背景があります」
- 「〜のような仕組みです」「〜という方法があります」
- 「〜を使えば解決できます」
- **具体的な事実や手順を示すことで、自然に安心感を与える**
- **「『〜と思った方もいるかもしれません』→ 具体的な解決策を示す」**という流れ

**使用ガイドライン**:
- **「大丈夫です」「安心してください」**: **原則使用禁止**。事実ベースの説明に置き換える
- 「実は」: 記事全体で1-2回まで（本当に驚きのある情報の場合のみ）
- 「簡単」「思ったより」: 過度な使用を避ける（「思ったより簡単」などの組み合わせは特に注意）
- 「簡単に言うと」: 記事全体で1回まで（多用すると上から目線に聞こえる）
- **時間の断言**: 「〇分で完了」「数分で終わる」「すぐに完了」などは避ける（事実ベースでない）
- 組み合わせ使用: 完全に避ける

**とまだ式の代替アプローチ**:
```markdown
❌ 「大丈夫です、このコマンドは簡単です」
✅ 「このコマンドは3つのステップで実行できます。まず〜」

❌ 「安心してください、失敗しても問題ありません」
✅ 「失敗しても git reset で元に戻せるので、気軽に試してみましょう」
```

### 締めくくりの不適切な表現

❌ **避けるべき（感情的な表現）**:
- 「楽しんでくださいね」
- 「楽しみましょう」
- 「ワクワクしますね」

✅ **推奨（行動促進型）**:
- 「まずは基本的な使い方から始めてみましょう」
- 「〜を使って、より効率的な開発を始めてみてください」
- 「次の手順で実際に試してみましょう」

## 絵文字の使用

### 過度な絵文字の使用

❌ **避けるべき**:
```
🔥🚀💯最強のツール
これはヤバい🔥🔥🔥
```

✅ **適度な使用**:
```
便利なツールです
これは効果的です
```

**原則**:
- 基本的に絵文字は使用しない
- 箇条書きのポイント表示（✅ ❌）は使用OK
- 過度な装飾絵文字（🔥🚀💯）は完全排除
